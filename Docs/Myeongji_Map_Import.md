# 명지대 맵 이관 현황

## 현재 사용 씬

- `Assets/_Game/Scenes/FourDistrictPrototype_Myeongji.unity`
- 원본 `FourDistrictPrototype` 씬은 보존한다.
- 2026-10-30부터 이 씬이 기준 게임 씬이다(사용자 결정). 타이틀 씬의 `SceneController` 게임 씬 이름을 이 씬으로 바꿔, 타이틀에서 시작하거나 다음 날로 넘어가면 여기로 들어온다. 예전 4구역 씬은 직접 열어 Play할 수 있다.
- 배치 단계 백업: `FourDistrictPrototype_Myeongji_LayoutBackup.unity`
- 맵 프리팹: `Assets/_Game/Prefabs/Myeongji/MyeongjiMap.prefab`
- 크기 135 × 119m, 건물 52채. Blender 1m = Unity 1m.
- 좌표: Blender (x,y,z) → Unity (x,z,y). FBX 루트 180도 회전으로 맞춤.

## 완료

- 주인공 이동, 물리, 안전 위치 복귀 및 3인칭 카메라 추적 재연결.
- 남쪽 C구역 H01 앞 집에서 시작. 시작점 (4.20,1.04,-86.00).
- 가게 12곳, 배달 지점 32곳, 집 1곳. 기존 주문의 가게/구역 인덱스는 유지한다.
- 새 건물 정면에서 캡슐이 설 공간과 도로까지 접근 공간을 확인하여 지점을 배치했다. 위치와 건물 대응은 `Docs/MapLayout/Myeongji/anchors.json`에 있다.
- 새 도로 18개를 복귀 위치 조회용 스플라인으로 연결했다. `MyeongjiRoutes`의 RoadNetwork/RoadSurface는 자동 메시 생성을 막기 위해 비활성화했지만 경로 조회는 가능하다. MeshRenderer도 꺼두어 Blender 도로 위에 표면이 중첩되지 않게 했다. 이 경로들의 시각 메시 재생성은 실행하지 않는다.
- 도로 교차점, 도로 폭 안의 근접 접속부, 지점별 접근선을 연결해 최단 도로 거리를 계산했다. 새 거리표는 `Assets/_Game/Settings/MyeongjiRouteTable.asset`이며 원본 거리표는 보존했다.
- 지도 배경을 새 건물/도로 도식으로 교체하고 좌표 범위를 (-10,-110), 크기를 (135,119)로 변경했다.
- 선택된 가게는 기존 목적지 안내로 표시되며 가게 바닥에 작은 금색 수령 마커를 두었다.
- SceneController의 게임 씬 경로를 직렬화 설정으로 변경했다. 기존 씬은 원래 기본값을 유지하고 이 씬은 다음 날에도 명지대 씬으로 돌아온다. 명지대 씬을 빌드 목록 끝에 추가했다.
- 사용자가 조정한 Scene 뷰 시점/투영은 이번 단계에서 변경하지 않았다.

## 현재 진행 상태

`Traffic`, `Pedestrians`, `Hazards`를 새 맵 좌표에 연결하고 활성화했다. 차량·행인·횡단보도 신호 연결 내역은 아래를 참고한다. 실제 주행과 신호 대기 흐름은 사용자 Play 확인이 필요하다.

새 거리표에 따라 주문 거리 입력은 줄었지만 시간/보상/하루 길이 등 기획 수치는 변경하지 않았다. 실제 플레이 후 필요할 경우 별도로 조정한다.

## 확인 범위와 사용 방법

Unity 편집기 컴파일 및 씬 저장 완료. 거리 그래프의 모든 지점 연결, 45개 지점의 정적 충돌 겹침 없음, 누락 스크립트 없음, 주인공/카메라/배달 참조 연결을 확인했다. 실제 Play 모드 및 자동 입력 테스트는 수행하지 않았다.

사용자는 명지대 씬을 직접 열고 Play를 눌러 이동, `1`번 콜 열기, 가게 자동 수령, 받는 사람 주먹 전달, `M` 지도 위치를 확인하면 된다. 타이틀부터 실행해도 이 씬으로 진입한다.

## 재생성 도구

- `Tools/MyeongjiGameplay.cs`: Pipeline run_script로 단계별 Prepare → ConnectData → Activate. Prepare는 기존 위치 루트가 있으면 중복 생성을 거부한다.
- `Tools/build_myeongji_routes.py`: Prepare가 저장한 anchors.json을 사용해 도로 거리표/연결 그래프/지도 배경을 만든다. 위치를 바꾼 경우 해당 JSON도 먼저 갱신해야 한다.
- 이 설치기들은 원본 씬을 대상으로 실행하지 않는다.

## 공용 시각 기능·개발자 도구 설치 (2026-10-30)

- 명지대 씬은 커브드월드 커밋 이전에서 갈라져 나와 아래 기능이 없었다. 원본 씬과 같은 설치기를 이 씬에도 실행했다. 설치기는 `GameScenes`에 등록된 두 게임 씬에서만 실행된다.
  - `Apply Curved World`: Lit 재질을 커브드월드용으로 바꾸고(명지대 재질 53개 포함), 카메라에 `CurvedWorld`를 붙이고, 월드 글자 13개가 굽힘을 따르게 했다. 곡률은 원본 씬과 같은 0.002다.
  - `Apply Day Sky`: `PilotSun`의 시간대 하늘·해 그림자·구름 그림자를 켰다. 3D 구름(`Clouds`)도 추가했다. 납작한 바닥·도로 부품 1,126개는 그림자를 만들지 않는다(`ST_Asphalt`, `ST_Pavement`, `ST_Plot`, `ST_Paint_White`, `ST_Paint_Yellow`, `PickupPoint`).
  - `Apply Sundial`: 해시계 UI.
  - `Apply Dev Tools`: F1 개발자 도구. 사건 값은 `MyeongjiHazardSpawnSettings`에 연결된다.
- `Buildings0.fbx` 재질 연결 수정:
  - 원인: FBX 재질 연결표의 이름은 `MJ01 | ...`(세로줄)인데 가져온 재질 이름은 `MJ01 _ ...`라서, 건물 `AB01_A01.001`은 꺼내 둔 `.mat` 대신 FBX 안의 재질을 쓰고 있었다.
  - 처리: `.meta`는 그대로 두고 `MyeongjiMap` 프리팹에서 이 건물의 재질 3개를 `Materials`의 `MJ01___*`·`STUDY___Plain_concrete`로 바꿨다. 그래서 이제 굽힘을 따른다.
  - 영향: 꺼내 둔 재질이 FBX 안 재질보다 밝아서(색공간 보정) 유리·콘크리트가 조금 밝아졌다.
- 근육맨 패턴은 아래 '인도 모퉁이 연결' 뒤에 추가했다.
- 확인: 컴파일, 누락 스크립트 0, 참조 연결, 편집 모드 렌더. Play 확인 전이다.
