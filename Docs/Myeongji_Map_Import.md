# 명지대 맵 이관 현황

## 현재 사용 씬

- `Assets/_Game/Scenes/FourDistrictPrototype_Myeongji.unity`
- 원본 `FourDistrictPrototype` 씬은 보존한다. 타이틀의 기본 진입 씬도 변경하지 않았다.
- 배치 단계 백업: `FourDistrictPrototype_Myeongji_LayoutBackup.unity`
- 맵 프리팹: `Assets/_Game/Prefabs/Myeongji/MyeongjiMap.prefab`
- 크기 135 × 119m, 건물 52채. Blender 1m = Unity 1m.
- 좌표: Blender (x,y,z) → Unity (x,z,y). FBX 루트 180도 회전으로 맞춤.

## 완료

- 주인공 이동, 물리, 안전 위치 복귀 및 3인칭 카메라 추적 재연결.
- 남쪽 C구역 H01 앞 집에서 시작. 시작점 (4.20,1.04,-86.00).
- 가게 12곳, 배달 지점 32곳, 집 1곳. 기존 주문의 가게/구역 인덱스는 유지한다.
- 새 건물 정면에서 캡슐이 설 공간과 도로까지 접근 공간을 확인하여 지점을 배치했다. 위치와 건물 대응은 `Docs/MapLayout/Myeongji/anchors.json`에 있다.
- 새 도로 18개를 복귀 위치 조회용 스플라인으로 연결했다. `MyeongjiRoutes`의 RoadNetwork/RoadSurface는 자동 메시 생성을 막기 위해 비활성화했지만 경로 조회는 가능하다. MeshRenderer도 꺼두어 Blender 도로 위에 표면이 중첩되지 않게 했다. 이 경로들의 시각 메시 재생성은 실행하지 않는다.
- 도로 교차점, 도로 폭 안의 근접 접속부, 지점별 접근선을 연결해 최단 도로 거리를 계산했다. 새 거리표는 `Assets/_Game/Settings/MyeongjiRouteTable.asset`이며 원본 거리표는 보존했다.
- 지도 배경을 새 건물/도로 도식으로 교체하고 좌표 범위를 (-10,-110), 크기를 (135,119)로 변경했다.
- 선택된 가게는 기존 목적지 안내로 표시되며 가게 바닥에 작은 금색 수령 마커를 두었다.
- SceneController의 게임 씬 경로를 직렬화 설정으로 변경했다. 기존 씬은 원래 기본값을 유지하고 이 씬은 다음 날에도 명지대 씬으로 돌아온다. 명지대 씬을 빌드 목록 끝에 추가했다.
- 사용자가 조정한 Scene 뷰 시점/투영은 이번 단계에서 변경하지 않았다.

## 현재 진행 상태

`Traffic`, `Pedestrians`, `Hazards`를 새 맵 좌표에 연결하고 활성화했다. 차량·행인·횡단보도 신호 연결 내역은 아래를 참고한다. 실제 주행과 신호 대기 흐름은 사용자 Play 확인이 필요하다.

새 거리표에 따라 주문 거리 입력은 줄었지만 시간/보상/하루 길이 등 기획 수치는 변경하지 않았다. 실제 플레이 후 필요할 경우 별도로 조정한다.

## 확인 범위와 사용 방법

Unity 편집기 컴파일 및 씬 저장 완료. 거리 그래프의 모든 지점 연결, 45개 지점의 정적 충돌 겹침 없음, 누락 스크립트 없음, 주인공/카메라/배달 참조 연결을 확인했다. 실제 Play 모드 및 자동 입력 테스트는 수행하지 않았다.

사용자는 명지대 씬을 직접 열고 Play를 눌러 이동, `1`번 콜 열기, 가게 자동 수령, 받는 사람 주먹 전달, `M` 지도 위치를 확인하면 된다. 타이틀부터 실행하면 기존 원본 씬으로 진입한다.

## 재생성 도구

- `Tools/MyeongjiGameplay.cs`: Pipeline run_script로 단계별 Prepare → ConnectData → Activate. Prepare는 기존 위치 루트가 있으면 중복 생성을 거부한다.
- `Tools/build_myeongji_routes.py`: Prepare가 저장한 anchors.json을 사용해 도로 거리표/연결 그래프/지도 배경을 만든다. 위치를 바꾼 경우 해당 JSON도 먼저 갱신해야 한다.
- 이 설치기들은 원본 씬을 대상으로 실행하지 않는다.

## 이벤트 이관 (2026-10-30)

- `Hazards`의 HazardPlanner를 활성화하고 MyeongjiRoutes, MyeongjiHazardCandidates, MyeongjiHazardSpawnSettings에 연결했다.
- 99개 도로 기준점에서 8종 합계 703개 후보를 생성했다. 맨홀 154, 소화전 121, 멜론 85, 돌출문 47, 오리 31, 닭 117, 타이어 59, 비둘기 음식 뺏기 89.
- 703개가 동시에 등장하는 방식이 아니다. 기존 HazardPlanner가 실행 시 간격 규칙을 적용해 일별 수량/트리거 풀을 선택한다. 서로 가까운 후보가 제외되므로 설정 수량보다 적게 배치될 수 있는 기존 동작은 유지한다.
- 수령·전달 지점 주변 기본 4m, 집 주변 11m를 제외했다. 닭은 배달 지점 7m/집 15m 여유를 두었다. 교차로, 건물, 기둥 충돌을 검사해 후보를 만들었다.
- 돌출문은 실제 벽을 찾아 붙이고 문이 열리는 영역을 검사했다. 명지대 전용 SwingDoor 프리팹에서 임시 Backing 벽만 제거했다. 원본 문과 다른 프리팹들은 유지한다.
- 타이어/오리는 도로 횡단 및 대기 공간, 비둘기는 16개 도주 지점의 공간을 확인했다. 추격 중 자유롭게 움직이는 닭의 모든 동작까지 검증한 것은 아니다.
- 새 도로 그래프의 12×32 경로와 후보 기준점을 연결했다. 384개 가게→배달 조합 모두 경로 주변 후보가 있다. 5개 기준점은 경로 외 후보이며 기존 무작위 배치 대상으로 남긴다.
- 원래 수량, 간격, 발동 조건, 날짜별 해금 규칙은 유지한다. 타이어·음식 뺏기는 2일차부터 해금된다. 일반 콜 트리거는 수령 후 발동하고 닭은 기존 예외 규칙을 따른다.
- 이전 상태 백업: `FourDistrictPrototype_Myeongji_BeforeEvents.unity`.
- 재생성 순서: Tools/MyeongjiEvents.cs의 Bake → Tools/link_myeongji_hazards.py → InstallAssets → Activate. 원본 대형 맵 설치 메뉴를 실행하지 않는다.
- 확인 범위: 편집기 스크립트 컴파일, 후보의 공간 조건 및 경로 연결, 전용 자산/프리팹 참조, 씬 저장. Play 모드·자동 입력·발동 시뮬레이션은 수행하지 않았다.

## 차량·행인·신호 이관 (2026-10-30)

- 차량 경로 41개 / 교차점 8개를 새 도로에서 구성했다. 폭 6m 이상 도로를 사용하고 좁은 골목은 제외했다. 차량 수는 시험값 12대이며 기존 승용차·택시·밴만 사용한다. 긴 버스는 제외했다.
- 기존 차량 추종·충돌·교차로 양보 로직을 유지했다. 회전 경로를 조정하고 가장 큰 차량의 공간 여유, 전체 경로 연결을 정적으로 확인했다.
- 행인 경로 78개 / 모퉁이 연결 4개, 시험값 24명. 실제 인도 재질 위이고 건물·기둥과 간섭하지 않는 구간만 사용한다. 행인은 인도를 왕복하며 이번 단계에 도로 횡단 행동은 추가하지 않았다.
- 큰길 횡단보도 x=8,36,101의 세 그룹에 차량 신호 6개 / 보행자 신호 6쌍을 연결했다. 각 그룹은 양쪽 접근 경로 2개에 정지선을 연결한다.
- 주기 시험값: 차량 초록 22초 → 노랑 3초 → 차량이 횡단보도를 벗어난 뒤 전체 빨강 2초 → 보행자 초록 8초 → 전체 빨강 2초. 각 Crossing 인스펙터에서 조정 가능하다.
- 차량은 신호가 정지 상태이면 정지선 앞에서 기존 추종 여유만큼 대기한다. 이미 앞부분이 정지선을 지난 차량은 통과시키고, 횡단 구간이 비워질 때까지 보행자 초록을 지연한다.
- 신호는 기존 빨강/초록 보행자 메시를 전환하고 차량 신호 렌즈의 색·발광을 제어한다. 일시정지와 정산에서는 주기를 멈춘다. 지도 UI를 열었을 때는 계속 흐른다.
- 런타임 추가: PedestrianCrossingSignal, TrafficNetwork의 선택적 signalStops. 신호 참조가 없는 원본 씬은 기존 동작을 유지한다.
- 편집 상태에서는 전체 빨강으로 표시하고, Play 시작 시 차량 초록/보행자 빨강부터 시작한다.
- 이전 상태 백업: FourDistrictPrototype_Myeongji_BeforeTraffic.unity.
- 재생성 순서: Tools/MyeongjiTrafficBake.cs Apply → Tools/MyeongjiPedestrianBake.cs Apply → Tools/MyeongjiSignals.cs Apply. 신호 설치 후 경로를 다시 구우면 signalStops의 경로 번호도 다시 연결해야 한다. 신호 설치기는 중복 생성을 거부한다.
- 확인: Unity 편집기 컴파일, 씬 저장, 경로/정지선 참조, 누락 스크립트 0. Play 모드·자동 입력·신호 시뮬레이션은 실행하지 않았다.
- 사용자 확인: 명지대 씬에서 차량과 행인이 이동하는지, 큰길의 보행자 초록 동안 차량이 횡단보도 앞에서 대기하는지 확인한다. 실제 혼잡도에 따라 수량·주기를 조절할 수 있다.
