# 사고 이동과 몸짓 통합 구현계획

- 작성일: 2026-10-14
- 요청: 분위기 이식의 1번(몸으로 보여주는 사고 반응)과 2번(날아가는 과정의 재미)을 함께 개선한다.
- 상태: 계획에 따른 캡슐 단계 구현·컴파일·씬 반영 완료. 실제 플레이 미검증. 추후 모델의 실제 래그돌 연결은 모델 추가 시 수행한다.
- 후속 사용자 지시: 현재 플레이어는 캡슐이며, 추후 모델 래그돌로 비행·조작 불가 중 흐느적거리는 표현을 구현한다. 이를 전제로 계획을 진행한다.
- 기준: [프로젝트 규칙](../project_rules.md), [프로토타입 기획서](배달라이더_프로토타입_기획서.md), [분위기 이식 분석](체험판_HTML_분위기_이식_분석.md).
- 사용자 지정 방향은 두 작업의 통합이다. 아래 상태·수치·구현 순서는 개발 제안이며, HTML 수치가 확정된 게임 규칙을 뜻하지 않는다.

## 1. 목표 경험

**맨홀에 맞아 몸이 뒤집힘 → 공중에서 방향을 조금 바꿈 → 벽에 부딪혀 튕김 → 바닥에서 한 번 튀고 구름 → 일어나 같은 배달을 계속함.**

물리 이동과 몸짓이 하나의 사고 흐름을 따른다. 비행 중의 몸 회전 속도, 충돌 순간 움츠림, 구르기와 일어나기는 실제 이동 상태·속도·접촉 결과에 연결한다. 사건 오브젝트가 끝나도 플레이어의 비행은 이어지고, 이동이 회복되면 외형도 정상 자세로 돌아온다.

첫 범위는 플레이어의 사고 발사·미끄러짐·충돌·착지·복귀와 캡슐 임시 몸짓이다. 일반 달리기·인라인의 기존 속도, 점프, 주먹 전달, 음식 복구, 주문 타이머와 경제는 유지한다. 추후 모델에는 실제 관절 래그돌을 연결하는 방향이다. 현재는 래그돌 연결에 필요한 상태·충격·복귀 알림을 구현하고 캡슐 임시 연출과 분리한다. 새 동물·소품 연쇄·트럭, 효과음·입자·의성어, 음식 낙하 확률은 후속 작업이다. 이번 계획으로 미정 콘텐츠를 채택하지 않는다.

## 2. 현재 구현과 바꿀 부분

| 현재 | 개선 |
|---|---|
| `RiderMotor`의 발사 속도 적용 후 사고 중 물리 이동만 진행 | 약한 공중 조종, 실제 접촉에 따른 반사·반발·감쇠 추가 |
| `DeliverySession.CanMove`가 사고 회복 중 false, 이동 입력도 0 | UI 허용 여부와 일반 이동·공중 조종·공격 허용 여부를 구분 |
| 최소 회복 시간 후 접지 또는 제한시간이면 즉시 속도 0 | 접촉과 속도로 비행→구르기→일어나기 전환. 제한시간은 막힘 복구에 사용 |
| 발사·미끄러짐·회복이 여러 bool과 시간으로 표현됨 | 작은 사고 상태 enum을 `RiderMotor` 안에서 관리하고 기존 공개 API는 호환 |
| 사고 몸짓 전용 컴포넌트 없음 | 외형 자식에만 자세를 적용하는 `RiderReactionVisual` 추가 |
| 카메라가 `IsRecovering`으로 비행 거리 확대 판단 | 실제 사고 비행 상태로 판단. 구르기·일어나기에는 거리 복귀 |
| 추락하면 저장된 위치로 복귀 | 안전 위치 조건 강화, 지붕·길 밖 정지·끼임에도 안전 도로 복귀 경로 제공 |

현재 `RoadSurface`는 시각 메시이고 지형 Collider 위에 놓인다. 복귀 위치는 도로 메시 Collider를 찾는 방식으로 만들지 않는다. `RoadNetwork`의 도로·지형 정보를 재사용하되 `Roads` getter가 매번 자식을 수집하므로 런타임 참조는 초기화 시 캐싱한다.

## 3. 구현 구조

### 이동을 결정하는 곳은 한 곳

`RiderMotor`가 사고 상태, 속도, 공중 입력, 접촉 반응, 회복과 복귀를 담당한다. 기존 `TryTrafficCrash`·`TryContactCrash`·`TryHazardCrash`·`TryHazardSlip`·`CancelSlip` 호출 형태를 유지한다. 사건 스크립트는 충격을 요청하고 실제 수락 결과를 확인한다.

`RiderReactionVisual`은 읽기 전용 상태와 실제 속도, 충돌 알림을 받아 외형 자세만 갱신한다. Rigidbody·Collider·주문·음식 보유 상태는 변경하지 않는다. 물리는 `FixedUpdate`와 충돌 콜백, 외형은 `LateUpdate`에서 반영하고 게임 시간에 따라 정지한다. 범용 상태 프레임워크나 새로운 입력 패키지는 만들지 않는다.

외형 설치 전 실제 플레이어 자식 구조와 메시를 확인한다. 메시만 `VisualRoot` 아래에 배치하고 Rigidbody·CapsuleCollider·카메라 target·공격 기준은 기존 루트에 유지한다. 기존 음식 가방은 위치·활성 제어를 보존하면서 몸과 함께 따라가게 한다. 현재 캡슐·머리·얼굴을 재사용하며 가짜 관절 인형을 추가하지 않는다. 팔다리의 흐느적거림은 모델 추가 전에는 검증할 수 없다. 기존 사용자 모델이 있으면 재사용하고 바인딩만 추가한다.

### 제안 상태와 입력

| 상태 | 물리와 조작 | 몸짓 | 다음 상태 |
|---|---|---|---|
| Normal | 기존 달리기·인라인·일반 점프·주먹 | 기존 외형 자세 | 사고 발사 또는 미끄러짐 |
| Airborne | 중력·약한 공중 조종·접촉 반사. 주먹·점프 차단 | 진행 방향을 축으로 공중제비, 팔다리 벌림 | 바닥 반발 후 비행 유지 또는 Rolling |
| Sliding | 기존 제한 조종·경사 미끄러짐. 주먹·점프 차단 | 뒤로 젖힘·팔다리 버둥거림 | 종료 후 Normal, 강한 벽 충돌이면 Airborne |
| Rolling | 지면 접선 속도를 감쇠, 입력 추진 없음 | 이동 방향으로 굴러가거나 낮은 속도에서 엎어짐 | 속도 안정 시 GettingUp |
| GettingUp | 지면 고정·짧은 회복, 공격 차단 | 바닥에서 일어남 | Normal |

`IsRecovering`은 Airborne·Rolling·GettingUp을 포함하는 호환 상태로 유지한다. Sliding은 기존 `IsSlipping`으로 판정한다. 공중 입력은 `session.CanMove`로 읽지 않고 일시정지·콜·지도·정산이 아닌 조건에서 별도로 읽는다. 일반 점프를 사고 비행으로 바꾸거나 정상 이동 입력 제한을 함께 풀지 않는다.

## 4. 물리와 연출 규칙

### 발사·비행

- 첫 단계에서는 기존 위험물의 발사 방향·세기를 유지한다. 맨홀의 접근 방향 반영은 후속 튜닝으로 구분하여 공중 조종 개선과 효과를 혼동하지 않는다.
- 발사 시 기존 속도를 요청 충격으로 대체하는 정책을 유지한다. 다중 사고에서 힘을 무제한 더하지 않는다. 평상시 달리기 속도 제한은 비행 속도에 적용하지 않는다.
- 공중 조종은 카메라 기준 수평 가속으로 궤적을 조금 수정한다. 입력으로 새로 얻는 속도에는 상한을 두되, 이미 발사로 얻은 큰 속도를 즉시 깎지 않는다. 일반 점프의 기존 동작과 사고 공중 조종을 구분한다.
- 비행 방향·속도를 외형에 전달한다. 수평 속도가 거의 0이면 마지막 유효 방향을 유지해 자세가 흔들리지 않게 한다. 시각 회전이 충돌체와 카메라 기준을 회전시키지 않는다.

### 벽·바닥 충돌

- 충돌 전 속도를 저장하고 접촉 법선에 대한 진입 속도로 반응을 계산한다. 바깥으로 나가는 접촉과 미약한 접촉에는 반사를 반복 적용하지 않는다.
- 벽에서는 법선 방향을 반사하고 접선 성분을 남긴다. 바닥에서는 강한 낙하에만 제한된 반발을 적용하고, 약한 낙하나 반발 횟수 소진 시 구르기로 전환한다. 경사에서도 지면 법선을 사용한다.
- 물리 재질의 반발과 수동 반사 계산을 중복 적용하지 않는다. Rigidbody의 실제 현재 충돌 설정과 재질을 에디터에서 확인한 뒤 한 방식으로 통일한다. 고속 관통 대응은 기존 Rigidbody 설정을 확인하고 필요한 범위만 보완한다.
- 한 물리 스텝의 여러 접촉점은 가장 강한 유효 접촉을 기준으로 한 번 처리한다. 지속 접촉·벽 모서리·경사에서 무한 반발이 발생하지 않게 최소 충돌 간격·횟수·속도 기준을 둔다.
- 몸짓은 벽 충돌에 움츠림과 회전 방향 전환, 바닥 반발에 몸 접기, 구르기에 진행 속도에 따른 회전을 적용한다. 접촉이 끝나면 기본 사고 자세로 돌아온다.

### 착지·회복

- 접지와 속도가 안정되는 순간 GettingUp으로 전환한다. 시간만 지났다는 이유로 공중 속도를 0으로 만들지 않는다.
- GettingUp 완료 때 Normal로 전환하고 외형의 로컬 위치·회전·크기를 초기값으로 복원한다. 새 사고·씬 종료·비활성화·정산·안전 복귀 시에도 잔여 자세와 지연된 결과를 정리한다.
- 동일한 재장전·연쇄 규칙을 유지한다. 다른 위험물의 유효 후속 발사는 진행 중 사고를 대체하며 자세도 새 속도로 갱신한다. 전환할 때 일반 이동을 잠깐 허용하는 틈을 만들지 않는다.
- 바닥·벽 반사는 새로운 위험물 피격으로 집계하지 않는다. `HazardHit`은 기존 실제 위험물 피격에서만 발생시켜 추가 점화를 남발하지 않는다.

## 5. 복귀·UI·주문 보장

- 안전 위치는 정상 상태에서 도로 범위 안의 접근 가능한 지면에 안정적으로 서 있을 때만 갱신한다. 사고 착지·지붕·소품 위·미끄러짐에서 덮어쓰지 않는다.
- 사고 제한시간에 도달했는데 안전하지 않거나, 지붕·길 밖에서 정지하거나, 일정 시간 위치 진행이 없으면 가까운 유효 도로 후보를 찾는다. 도로 표본을 캐싱하고, 필요할 때만 거리·지형 높이·캡슐 여유 공간을 확인한다. 찾지 못하면 마지막 안전 위치, 그것도 없으면 시작 위치의 안전 후보를 사용한다.
- 첫 복귀 연출은 기존 순간 복귀와 카메라 초기화를 재사용한다. R 수동 복귀도 같은 경로를 사용하도록 추가하는 안이다. 포물선 복귀 연출은 후속 작업이다. 복귀로 타이머·지각·음식·활성 주문을 초기화하지 않는다.
- 지도에서는 공중 입력과 새 공격을 막고 사고 물리는 계속 진행한다. 기존 미끄러짐 취소 정책을 유지하되 외형도 함께 정리한다. 일시정지·콜에서는 물리와 몸짓 시간을 함께 멈춘다.
- 정산에서는 사고 상태와 속도·외형을 정리한다. `DeliverySession`의 `CanMove`·`CanPickup`·`TryDeliver` 방어를 유지하므로 사고 비행 충돌만으로 수령·전달하지 않는다.
- 음식 탈취가 사고와 겹쳐도 추격 대상과 재수령 경로를 보존한다. 음식 낙하·확률 손실은 이번 작업에 추가하지 않는다.

## 6. 시험값 시작안

아래는 조정 출발점이다. 직렬화 설정으로 분리하고 실제 체감으로 변경한다. 현재 위험물 발사 세기는 우선 유지한다.

| 항목 | 제안 시작값 |
|---|---|
| 사고 공중 조종 가속 | 5m/s² |
| 공중 입력으로 얻는 수평 속도 상한 | 10m/s (기존 발사 속도 즉시 제한 금지) |
| 벽 법선 반사 계수 / 바닥 반발 계수 | 0.5 / 0.35 |
| 바닥 반발 최소 진입 속도 / 최대 횟수 | 5m/s / 2회 |
| 접촉 반응 최소 간격 | 0.12초 |
| 구르기 감속 / 일어나기 진입 속도 | 8m/s² / 1.5m/s 이하 |
| 안정 접지 시간 / 일어나기 시간 | 0.15초 / 0.45초 |
| 비행 외형 회전 | 속도에 따라 초당 180~540도 |
| 강한 접촉 자세 강조 | 0.12초 |
| 진행 없는 사고 복구 / 사고 전체 안전 제한 | 2초 / 8초부터 조정 |

위 계수는 HTML 값을 그대로 이식하지 않는다. 단순 지속시간 교체로 기존보다 모든 사고가 길어지지 않게, 약한 충격은 빨리 회복하고 강한 충격은 멀리 이동하는 차이를 목표로 한다. 정상 이동 속도를 낮춰 균형을 맞추지 않는다.

## 7. 구현 순서와 변경 파일

| 단계 | 함께 구현할 이동·몸짓 | 완료 기준 |
|---|---|---|
| A | 플레이어 외형 조사·VisualRoot 연결, 작은 사고 상태, 발사 자세·공중 조종 | 맨홀 발사에서 궤적을 조금 바꾸고 몸이 같은 방향으로 회전 |

## 8. 검증과 완료 기준

구현 시 코드 검토와 최소 컴파일 오류 확인, 에디터 반영·저장 확인을 수행한다. 별도 요청 없이 Play 모드·자동 입력·검증용 플레이 코드를 실행하지 않는다. 아래는 사용자에게 제공할 수동 확인 절차다.

1. 맨홀: 입력 유무로 착지 위치가 달라지고, 회전 외형이 실제 비행을 따라가는지 확인.
2. 벽·경사 착지: 한 접촉에 한 번 반응하고 속도가 감소하는지, 벽·바닥에서 계속 튀지 않는지 확인.
3. 수박: 조종을 조금 남긴 미끄러짐과 자세가 함께 시작·종료되는지, 벽 충돌 전환이 과장되지만 읽히는지 확인.
4. 연속 문·타이어: 기존 재피격 간격·연쇄 집계를 유지하면서 새 발사가 이전 동작과 몸짓을 함께 대체하는지 확인.
5. 지도·일시정지: 지도는 사고가 진행되고 공중 입력이 멈추며, 일시정지는 몸짓과 사고가 함께 멈추는지 확인.
6. 지붕·끼임·추락·R 복귀: 안전 도로로 복귀하고 음식·목표·지각이 유지되는지 확인.
7. 정상 플레이: 점프가 사고 회전으로 바뀌지 않고 주먹 전달·음식 복구·마지막 주문 정산이 기존대로 되는지 확인.

판단 기준은 ‘입력으로 결과를 조금 바꿀 수 있음’, ‘몸짓과 실제 상태가 맞음’, ‘충돌이 다음 이동으로 이어짐’, ‘일어나면 즉시 배달을 계속할 수 있음’이다. 완료 후 기획서 13절과 분위기 분석의 현재 상태를 갱신하고, 파일 작성·컴파일·에디터 적용·실제 플레이 수준을 구분해 보고한다.

## 9. 모델·래그돌 추가 시 연결

- 이동 상태는 `RiderMotor.ReactionState`이며, `ReactionChanged`는 상태가 바뀔 때만 알린다. 같은 비행 중 후속 충격은 `ReactionImpulse(Vector3)`로 별도 전달한다. 값은 월드 공간의 반응 후 속도이므로 뼈의 질량별 힘으로 그대로 적용하지 않고 모델 연출에서 해석한다. `Velocity`·`HorizontalSpeed`는 실제 이동 속도이고 `SafePositionRestored`는 강제 위치 복귀 알림이다.
- 현재 `RiderReactionVisual`은 캡슐 전용 임시 연출이다. 모델이 들어오면 이 컴포넌트를 제거하거나 비활성화하고, 모델의 애니메이션·래그돌 전환 담당이 같은 알림을 구독한다. 캡슐 회전·스케일 연출을 래그돌 뼈에 중복 적용하지 않는다.
- 정상 이동에서는 모델 애니메이션, 사고 비행·구르기 같은 조작 불가 상태에서는 래그돌, 일어나기에서는 모델의 회복 연출로 전환하는 방향이다. 미끄러짐 표현과 전환 방식은 실제 모델의 리깅·애니메이션을 확인해 조정한다.
- 모델 추가 시 골반·뼈·Joint·충돌 레이어·루트 위치 정렬을 설정한다. 이동 캡슐과 신체가 서로 밀지 않게 하고, 비행을 담당하는 루트와 골반의 추적 책임을 명확히 한다. 뼈를 매 프레임 강제로 옮기며 물리와 경쟁하지 않는다. 원점 복귀·정산·비활성화에서 모든 뼈의 속도와 자세를 정리한다.
- 이번 구현은 상태와 알림 연결까지다. 실제 래그돌 몸체·Joint·Animator 전환, 신체 관통·발산, 흐느적거리는 체감은 모델이 준비된 뒤 구현·검증한다. 캡슐 설치기를 모델 설치기로 간주하지 않는다.

## 10. 캡슐 단계 구현 기록 (2026-10-14)

- `RiderMotor`의 공개 사고 요청 API를 유지하고, 같은 타입의 `RiderMotor.Reaction.cs`에 사고 상태와 공중 조종·접촉 반사·구르기·일어나기를 분리했다. 미끄러짐 벽 충돌은 비행으로 전환한다. 벽·바닥 충돌은 `HazardHit`을 발생시키지 않아 연쇄 추가 점화와 구분된다.
- 공중 조종은 UI에서 차단하고 일반 공격을 허용하지 않는다. 지도에서는 사고 물리가 진행되고 일시정지에서는 게임 시간으로 멈춘다. `ThirdPersonCamera`는 회복 전체가 아닌 실제 사고 비행 상태를 참조한다. 벽·바닥의 유효 반발은 공통 카메라 충격 알림에 연결했다.
- `RiderReactionVisual`은 회전·기울기·짧은 압축과 일어나기를 외형 자식에만 적용한다. 현재 캡슐·Head·Face·FoodBag을 재사용하고, 플레이어 루트 Rigidbody·CapsuleCollider와 기존 참조는 보존했다. 외형 아래 Collider는 0개다.
- `RiderSafeRecovery`는 도로 중심을 초기 캐싱하고 도로 지형·캡슐 여유 공간을 확인한다. 사고 중 안전하지 않은 곳에서 정지하거나 안전 제한시간이 끝나면 도로 복귀하며, R도 같은 경로를 사용한다. 안전 위치를 미끄러짐·사고 중에 덮어쓰지 않는다. 주문·음식 보유·타이머는 복귀 코드가 수정하지 않는다.
- `Delivery Rider/Apply Rider Reactions` 설치기로 에디터 API 연결·저장을 수행했다. 반복 적용 후 연출·복귀 컴포넌트 각 1개, 외형 자식 연결과 `FourDistrictPrototype` 씬 저장 성공을 확인했다. 새로운 `.meta`는 Unity가 생성했다.
- 최종 변경은 Unity 컴파일 오류 0·경고 0. Play 모드나 자동 입력은 실행하지 않았다. 8절 절차로 반사·착지·공중 조종·복귀 체감을 직접 확인해야 한다. 현재는 캡슐 임시 몸짓이며 실제 팔다리 래그돌 구현 완료가 아니다.

## 11. 일반 점프 착지 보정 수정 (2026-10-14)

- 사용자 보고: 점프에서 바닥 착지가 부자연스러움. 코드와 에디터 설정을 확인했으며 실제 플레이 재현은 실행하지 않았다.
- 확인한 원인: `followSlopes`가 켜진 씬에서 최대 0.3m의 지면 탐색을 일반 점프 하강에도 적용하고 있었다. 바닥 접촉 전에 Rigidbody 위치를 아래로 보정하고 수직 속도를 지면 접선 속도로 교체하며 중력을 상쇄할 수 있었다. 낙하가 갑자기 끊기거나 바닥으로 당겨지는 원인이 된다.
- 수정: 가까운 지면 지지 판정(`groundContactTolerance`, 시험값 0.03m)과 이미 걷던 경사길의 넓은 지면 추종(`groundReach`, 기존 0.3m)을 분리했다. 일반 점프가 끝나기 전에는 넓은 지면 추종을 금지하며, 점프 시작 때 접지 상태를 즉시 해제한다. 중력 상쇄·접선 이동은 접지일 때만 적용한다.
- 지면 조회에서 플레이어 자신과 자식 Collider를 명시적으로 제외했다. 사고 발사·안전 복귀는 일반 점프 상태와 남은 점프 요청을 정리한다. 사고 반발과 일반 점프는 계속 분리한다.
- 접지 시 이탈 속도는 월드 Y가 아닌 지면 법선 방향으로 판단한다. 경사길을 올라가는 접선 이동의 상승 속도를 점프 이탈로 잘못 판단하지 않게 했다.
- 확인 환경: 중력 -9.81, 점프 초기 속도 5.5, 물리 간격 약 0.02초, Rigidbody damping 0·중력 사용·회전 고정·ContinuousDynamic·Interpolate. 전역 물리 설정과 이동 속도는 변경하지 않았다.
- 컴파일 오류 0·경고 0 확인. 에디터에서 새 지면 허용값을 반영·저장한 뒤, 사용자는 평지 제자리 점프·이동 점프·경사길 하강 점프·맨홀 사고 착지를 비교한다. 공중에서 낙하가 미리 끊기지 않는지, 착지 전 위치가 크게 당겨지지 않는지, 경사길 보정이 유지되는지 확인한다. 실제 체감 개선은 플레이 미검증이다.

## 12. 사고 자세 회복·부유·강제 복귀 수정 (2026-10-14)

- 사용자 보고: 사고 중 자세를 회복하지 못하고 떠 있다가 도로 중심으로 강제 복귀함. 코드상 복귀 조건과 외형 높이 보정을 수정했다. 발생 순간의 플레이 재현은 수행하지 않았다.
- 기존 구르기→일어나기는 도로 안전 판정 `IsSafe`까지 요구했다. 이를 제거해 걸을 수 있는 바닥에 안정적으로 멈추면 도로·인도·도로 밖에서 현재 위치 회복을 진행한다. 도로 판정은 저장할 안전 위치와 강제 복귀 목적지 선정에만 남긴다. 지붕 등에서 조작 회복 후 벗어나기 어려우면 R 복귀를 사용할 수 있다.
- 사고 접지는 최근 실제 바닥 충돌 접촉과 지면 탐색을 함께 사용한다. 정지한 물리 충돌체의 접촉 여유 간격을 탐색에 포함하되 일반 점프 허용값은 바꾸지 않는다. 새 발사·복귀에서 지난 바닥 접촉은 초기화한다.
- 구르기·일어나기에서 중력 상쇄를 제거했다. 착지한 상태에는 2초 도로 밖 정지 복귀·8초 사고 제한시간 복귀를 적용하지 않는다. 지지 바닥이 없는 상태에서 정지·시간 초과, 추락, R 요청에만 복귀 경로를 사용한다.
- 캡슐 외형은 누운 각도에 따른 지면 방향 크기로 높이를 보정한다. 일어나는 동안 회전과 높이를 함께 되돌린다. 루트의 이동용 캡슐은 유지하며 이 보정은 `RiderReactionVisual`의 임시 캡슐 표현에만 적용한다. 모델 래그돌에는 별도로 신체 충돌·위치 정렬을 연결해야 한다.
- 확인 절차: 도로·인도·도로 옆 평지에서 발사 후 정지하여 제자리 회복되는지, 8초가 지나도 착지한 플레이어가 강제 이동하지 않는지, 누운 외형이 지면 위에 붕 뜨지 않는지, 일반 점프·사고 반발·R 복귀가 유지되는지 확인한다. 컴파일과 에디터 설정 저장은 확인하며, 실제 플레이 체감은 미검증이다.
