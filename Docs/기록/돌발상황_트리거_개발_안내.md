# 돌발상황 트리거 — 9번

## 구현 범위

- 구역 진입 → 트리거의 이벤트 선택 → `IncidentDirector`에 전달 → 실행 프리팹 생성 → 생성된 오브젝트의 행동 → 정리.
- 모든 이벤트 스팟은 진입마다 실행한다. 구역·종류·전체 쿨타임과 하루 횟수 제한은 없다. 진행 중 사건이 있으면 정리하고 새 사건을 실행한다.
- `IncidentTrigger`는 연결된 설정 목록 중 하나를 선택한다. 한 항목만 연결하면 고정 종류다.
- 한 번 진입하면 한 번 실행한다. 계속 서 있는 동안 반복하지 않고, 나갔다가 다시 들어오면 즉시 다시 실행한다. 여러 후보 중 가중치로 종류를 선택하며 발생 확률 실패는 없다.
- 설정 자산에는 실행 상태를 저장하지 않는다. 다음 씬 시작 시 횟수와 대기 상태가 초기화된다.
- 첫 사건은 경고 후 구역에 남아 있으면 튕겨 나가고 잠시 조작할 수 없는 사고다. 차량 모델·차량 AI는 아직 없다.
- 경고는 0.8초이며 경고 후 구역 밖으로 벗어나도 충격은 실행한다. 주황색 바닥은 이벤트 범위를 보여주는 프로토타입 표시다.
- 지도에서도 사건 시간과 물리는 흐른다. 일시정지에서는 함께 멈춘다. 사고 중 수령·전달은 불가하고 회복 후 가능하다.
- 주문 시간은 초기화하지 않는다. 주문 없이도 사고가 발생하고, 영업 종료 후 마지막 주문에도 작동한다. 정산·씬 종료 시 사건을 정리한다.

모든 수치는 테스트 시작값이며 확정 밸런스가 아니다. 도난·시간 주기 트리거는 후속 단계다.

`Assets/_Game/Settings/Incidents/`에서 충격과 경고·회복 시간을 변경한다.

## 구역 추가 방법

1. 기존 사고 구역을 복제해 원하는 위치로 옮긴다.
2. `IncidentTrigger > Events`에 원하는 설정 자산을 연결한다. Weight는 후보 간 상대 비중이다.
3. 후보의 Weight로 이벤트 종류 선택 비중을 조절한다. 발생 확률·쿨타임·횟수 제한 설정은 제거했다.
4. Box Collider 크기를 조절한다. 바닥 표시 크기도 함께 맞춘다. 최종 아트 단계에서는 바닥 표시를 제거해도 된다.
5. 구역의 파란색 Z축이 충격 방향이다. 별도 Transform을 Impact Direction에 지정해도 된다.

같은 사고의 변형은 Project 창에서 Crash 설정 자산을 복제한다. 설정의 `Actor Prefab`에는 `CrashIncidentActor`가 붙은 실행 프리팹을 연결한다. 트리거의 `Actor Spawn`을 지정하면 그 위치·회전으로 생성하고, 지정하지 않으면 트리거의 위치·회전을 사용한다.

## 이벤트 실행 구조

1. `IncidentTrigger`: 플레이어 진입을 감지하고 가중치로 설정 자산을 선택한 뒤 `IncidentDirector.TryStart`에 전달한다. 시간형 발생도 같은 선택 경로를 사용한다.
2. `IncidentDirector`: 진행 중 사건을 정리하고 설정의 `Actor Prefab`을 생성한다. 추격형 도난이면 도둑도 지정된 `Thief Spawn`에 생성해 실행 오브젝트에 전달한다.
3. `IncidentActor`: 전달받은 설정과 트리거를 사용해 `Execute`에서 행동한다. 사고는 `CrashIncidentActor`가 경고·충격·회복을 수행하고, 도난은 `TheftIncidentActor`가 음식 분실과 복구 흐름을 진행한다. 음식이 없으면 도난 시도만 실행한다. 도둑의 경로 이동·충돌 회수는 `FoodThief`가 수행한다.

설정 자산은 수치·조건·프리팹 참조만 보유하며 생성이나 실행 코드를 갖지 않는다. 행동의 중단 처리는 실행 오브젝트의 `try/finally`에서 수행하고, 생성된 실행 오브젝트·도둑의 비활성화와 삭제는 `IncidentDirector`가 담당한다. 주문 상태 변경은 `DeliverySession`의 명시적인 메서드로 요청하며 사건 코드가 보상을 직접 지급하지 않는다.

기본 실행 프리팹은 `Assets/_Game/Prefabs/CrashIncident.prefab`과 `TheftIncident.prefab`이다. 둘은 행동을 관리하는 빈 오브젝트이며, 사고의 차량 모델이나 차량 이동은 추가하지 않았다. 기존 경고·충격·회복 방식은 유지한다. 도난의 실제 캐릭터는 `FoodThief.prefab`으로 생성한다.

동작이 다른 사건을 추가하려면 `IncidentDefinition`을 상속한 설정 타입과 `IncidentActor`를 상속한 행동 컴포넌트를 만들고, 행동 컴포넌트가 붙은 프리팹을 `Actor Prefab`에 연결한다.

`Delivery Rider > Install Incident Actor Prefabs`는 기존 사고·도난 자산에 누락된 실행 프리팹을 연결한다. 기존 프리팹 참조와 조정값은 유지한다.

메뉴 `Delivery Rider > Install Incident Zones`는 누락 요소 설치용이다. 기존 구역의 위치·목록·수치와 기존 설정 자산의 수치는 덮어쓰지 않는다.

## 직접 플레이 확인

1. 주문을 수락하고 남쪽 도로의 주황색 구역으로 진입한다. 경고 후 머무르면 충격, 회복 후 이동이 가능해야 한다.
2. 주문 없이도 사고가 발생하는지, 경고 후 밖으로 나가도 충격이 실행되는지 확인한다. 나갔다 즉시 다시 진입하면 쿨타임 없이 다시 발생해야 한다.
3. 사고 중 M으로 지도를 열고 닫아도 충격과 회복 시간이 이어지는지 확인한다. Esc 일시정지 중에는 멈춰야 한다.
4. 음식 수령 후 사고가 나도 주문과 음식이 유지되고, 회복 후 고객 충돌로 정상 전달되는지 확인한다.
5. 구역에 계속 서 있는 동안 재발동하지 않는지, 다른 구역에서도 사건 중복이 차단되는지 확인한다.

자동 Play 모드 진입, 입력 시뮬레이션 및 화면 캡처는 수행하지 않는다.
