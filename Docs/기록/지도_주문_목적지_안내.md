# 지도·주문 선택·목적지 안내 (4~6번)

> 사용자가 본 단계의 정상 동작을 확인했다. 이후 7~8번에서 실제 시간 계산·보상·하루 정산을 추가했다. 최신 동작은 [시간·보상·정산 안내](시간_보상_정산_안내.md)를 참고한다. 아래는 지도 구현 당시 기록이다.

## 이번 구현

- 기존 주문 창을 지도와 주문 상세 영역으로 확장했다. 게임 시작 및 배달 완료 시 지도를 열어 다음 주문을 선택한다.
- M 또는 닫기 버튼으로 지도를 열고 닫는다. 지도에서 Esc는 지도 닫기, 일반 플레이에서 Esc는 일시정지다.
- 지도에서는 이동·시점 회전·수령 조작을 막고 커서를 표시한다. 지도는 게임 시간을 멈추지 않는다. 일시정지는 시간을 멈춘다.
- 주문 없는 상태에서도 지도를 닫고 동네를 걸을 수 있다. M으로 다시 주문을 확인할 수 있다.
- 지도는 북쪽 고정이며 월드 X/Z 좌표를 사용한다. 기존 도로·건물 위치를 단순한 평면 도형으로 표시한다.
- 플레이어 위치와 방향, 음식점 3곳, 고객 프로필과 주문 번호를 표시한다. 같은 고객에게 주문이 겹치면 후보 마커를 나란히 놓고 실제 위치까지 연결선을 표시한다.
- 프로필을 누르면 기존 주문 상세·수락 로직으로 연결한다. 선택한 주문의 음식점과 고객을 강조하고 내 위치 → 수령지 → 고객을 선으로 연결한다.
- 배달 중 지도를 다시 열면 활성 주문 상세와 목적지를 표시한다. 다른 후보 수락은 막으며 기존 배달은 유지한다.
- 수령 전에는 음식점, 수령 후에는 고객으로 목적지가 바뀐다. 현장 바닥 원과 상단 표식, 화면의 거리 표시를 제공한다.
- 목적지가 화면 밖에 있으면 가장자리의 화살표로 방향을 표시한다. 주민이 밀리면 지도와 현장 안내가 주민을 따라간다.

지도 선은 직선 연결이며 길찾기 경로가 아니다. 지도 바깥으로 이탈한 위치는 가장자리에 제한해 표시한다. 한글 프로필은 간단한 사람 아이콘과 주문 번호를 사용한다.

## 조작

| 키 / 버튼 | 동작 |
|---|---|
| M | 지도 열기·닫기 |
| 고객 프로필 | 주문 상세 선택 |
| 주문 수락 | 선택 주문 수락 후 지도 닫기 |
| WASD / 마우스 | 지도 닫힌 상태에서 이동·시점 회전 |
| E | 지정 음식점에서 수령 |
| Esc | 지도 닫기 또는 일시정지·계속하기 |

## 사용자 확인 순서

1. 타이틀에서 시작하여 지도, 프로필 3개, 음식점 표시가 보이는지 확인한다.
2. 서로 다른 프로필을 선택할 때 상세 정보와 음식점 강조·연결선이 바뀌는지 확인한다.
3. 수락하면 지도가 닫히고 음식점으로 안내되는지 확인한다.
4. 이동 중 M으로 지도를 열어 플레이어 위치·방향을 확인한다. 지도 조작 중 캐릭터와 카메라가 움직이지 않는지 확인한다.
5. 배달 중에는 수락 버튼이 비활성화되고 다른 주문으로 바뀌지 않는지 확인한다.
6. 음식을 수령하면 안내가 고객으로 바뀌고, 카메라를 돌려도 화면 가장자리 화살표로 찾을 수 있는지 확인한다.
7. 고객 전달 후 지도가 다시 열리고 새 후보가 보충되는지 확인한다. 같은 고객의 후보가 겹치면 각각 선택 가능한지 확인한다.
8. 지도 닫기·일시정지·계속하기를 반복하여 커서와 이동 입력이 정상 복귀하는지 확인한다.

실제 플레이와 화면 검증은 사용자가 담당한다. 금액·제한 시간은 기존처럼 정보 표시용이며 실제 타이머와 보상 지급은 다음 7~8번 작업이다.

## 제작 확인

Unity 에디터 API로 GameScene에 지도·버튼 참조·목적지 안내를 연결하고 저장했다. 최종 저장 시 컴파일 실패 없음과 Play 모드 미실행을 확인했다. 씬 구성 중 컴포넌트 추가 및 TMP 참조 문제는 생성 코드에서 수정했다. 플레이 실행·입력 시뮬레이션·화면 캡처는 수행하지 않았다.
