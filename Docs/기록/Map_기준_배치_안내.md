# Map 기준 GameScene 배치

- 적용일: 2026-10-13
- 씬: `Assets/Scenes/GameScene.unity`
- 기준 맵: `Assets/Prefab/Map.prefab` — `MapLoader`가 실행 시 생성한다.
- Map 원본은 유지하고 배달 오브젝트를 중앙 도로 주변의 연결된 구역에 재배치했다.

## 배치

아래는 부모 이동을 포함한 월드 좌표다. 시작점과 주민은 Y=1.135, 수령 지점은 Y=1.018, 사건 중심은 Y=1.535다.

수령 지점은 그룹 단위로 옮겨 이름표와 음식 표시를 함께 유지했다. 카운터 2개도 건물 충돌체를 피하도록 위치·방향을 조정했다. 기존 주문 6개의 설정·수령지·고객 참조와 제한 시간, 이동 속도, 사건 간격은 유지한다.

## 도둑 경로

좌표의 Y는 모두 1.035다. 기존 생성점과 경유점 오브젝트를 유지하며 도로에 맞게 옮겼다.

- WestTheftZone: 생성 `(-24, 12)` → 경유 `(-3, 28)` → 도주 `(-3, 34)`. 총 약 32.4m.
- SouthTimedTheft: 생성 `(-33, -6)` → 경유 `(-22, 7)` → 도주 `(-11, 20)`. 총 약 34.1m.

## 지도

- 표시 범위: X=-45~35, Z=-30~50, 북쪽 고정.
- 실제 Asphalt·Sidewalk 메쉬와 회전한 건물 충돌체의 평면 형태를 지도 배경으로 반영했다.
- 배경 자산: `Assets/_Game/Art/MapGeometry/NeighborhoodMap.png`.
- 기존 지도 `Block_*` 9개는 삭제하지 않고 비활성화했다. 새 배경은 마커·버튼 아래에 있고 입력을 가로채지 않는다.
- 지도는 현재 배달 구역을 표시한다. 전체 맵 탐색·확대·축소 기능은 추가하지 않았다.
- Map 형상을 변경하면 이 배경도 갱신해야 한다. 플레이어·고객·음식점·도둑 마커는 기존처럼 현재 월드 위치를 따른다.

## 확인한 범위

- Unity 에디터 API로 적용하고 GameScene 저장 성공과 미저장 변경 없음 확인.
- 플레이어·주민·고객·카운터와 Map 건물 충돌체의 정적 겹침 없음 확인.
- 실제 FoodThief 충돌체를 사용해 도주 선분을 0.25m 간격으로 검사했고 건물 겹침 없음 확인. 남쪽 경유점은 검사한 동일 선분의 중간점이다.
- 도로·보도에서 건물 여유 공간을 제외한 1m 격자의 연결성을 확인했다. 지점들이 같은 연결 구역에 속한다. 이는 실제 플레이 검증을 대체하지 않는다.
- 주문 6개의 참조, 지도 배경 연결·레이어 순서, EventSystem 1개 유지 확인.
- 최종 에디터 상태: 컴파일 실패 없음, 콘솔 오류 없음, Play Mode 미실행.

## 사용자 확인 순서

1. GameScene을 실행해 시작점에서 건물에 끼지 않고 이동하는지 확인한다.
2. M 지도의 도로·건물 형태와 음식점·고객 표시를 비교한다.
3. 세 음식점의 주문을 각각 수락해 표시 범위에 들어가 자동 수령한 뒤 해당 고객을 주먹(F·클릭)으로 쳐서 전달한다.
4. 서쪽 보라색과 남서쪽 파란색 구역에서 추격 회수 및 도주 후 재수령을 확인한다.
5. 북쪽 보라색 구역에서 즉시 재수령, 주황색 구역 두 곳에서 사고 후 이동 복구를 확인한다.

실제 조작·충돌 반응·동선의 재미·지도 가독성은 사용자 플레이 확인이 필요하다.
