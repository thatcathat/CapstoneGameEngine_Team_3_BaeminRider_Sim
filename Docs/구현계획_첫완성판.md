# 첫 완성판 개발 흐름

기준: [기획서](배달라이더_프로토타입_기획서.md). 2026-10-15 현재 구현 기록을 요약했다.
목표는 집 출발부터 배달·정산·다음 날·상환 엔딩까지 한 판이 이어지는 것이다.

| 단계 | 목적 | 상태 |
|---|---|---|
| M0 | 본 게임을 FourDistrictPrototype으로 이전 | 구현됨 |
| M1 | 수동 콜·수령 후 타이머·해시계 | 구현됨 |
| M2 | 주먹 전달·점프·고객 반응 | 구현됨 |
| M3 | 현재 구역 수령·다른 구역 배달 | 구현됨 |
| M4 | 생활비·인라인·저장·다음 날·엔딩 | 구현됨 |
| M5 | 오브젝트/트리거·콜별 활성화·연쇄 | 구현됨 |
| M6 | 이삿짐 트럭 고정 사건 | 미착수 |
| M7 | 주소 오입력·요청 팁 1종 | 미착수 |
| M8 | 통합 플레이 확인·밸런스·실행 빌드 | 미착수 |

구현됨은 실제 플레이 통과를 의미하지 않는다. M0~M5는 컴파일·에디터 반영 기록이 있으나 플레이는 미검증이다.

## 이후 진행

1. 트럭 사건: 전조 → 작은 낙하물 → 큰 가구 → 정점 → 종료. 배달과 병행하고 끝나면 잔여 장애물을 정리한다. 시간·보상·조기 종료 목표는 시험안이다.
2. 주소 오입력과 요청 팁: 목적지가 바뀌어도 주문을 이어가고, 요청 실패는 팁에만 영향을 준다. M7은 M6와 독립적으로 진행 가능하다.
3. 사람이 한 판을 플레이해 시간·수익·사건 밀도·교통을 조정하고 저장 재개와 엔딩까지 확인한다.

별도로 도로·차량·행인, 사고 이동·몸짓·카메라를 보완했다. 최근 이동속도 2배와 차량 플레이어 감지 후 제동 지연 2초를 적용했다.
고양이·근육맨·추가 콜 상황·경찰·공룡·용암·도움 장치는 이후 선정 범위다.
작업은 필요한 코드 변경 → 최소 컴파일 확인 → 필요한 씬 반영 → 사용자 플레이 확인 순으로 진행한다.
