## 1. 첫 완성판의 정의

집에서 출발 → 1번 콜 → 현재 구역 수령 → 다른 구역 문 앞 → 주먹 전달 → 반복 → 마감 → 정산(생활비·구매) → 다음 날 → 빚을 모으면 일괄 상환 → 엔딩. 이 흐름이 4구역 맵에서 끊김 없이 한 바퀴 돌아야 한다.

| 포함 | 제외 (다음 확장) |
|---|---|
| 해시계, 수령 시 배달 타이머, 1번 콜 화면(2건) | 칼시간·급행·묶음 등 콜 상황 8종 |
| 주먹 전달·받는 사람 날아감, 점프 | 고양이 복서·근육맨·자리 없는 상황 3종 |
| 구역 순환 주문(가게 12·문 32), 큰길 거리 기반 보상·제한시간 | 경찰·공룡·용암, 두 사건 동시 진행 |
| 달리기·인라인, 생활비·빚·저장·엔딩 | 450곳 전체 배치와 57콤보 |
| 오브젝트/트리거 구분과 콜별 활성화, 대표 사건 6~8종, 작은 연쇄 | 소리 지르기 대상 전체, 대포·매트리스·환풍기 |
| 이삿짐 트럭 고정 사건 1종 | 아침 뉴스 연출 |
| 주소 오입력, 요청 사항·팁 1종 | |

수치는 전부 시험값으로 설정 자산에 두고, 사람이 직접 플레이한 결과로 조정한다.

## 2. 마일스톤 개요

| 단계 | 묶음 | 끝나면 사용자가 볼 수 있는 것 | 선행 |
|---|---|---|---|
| M0 | 본 씬 이전 | 타이틀 → 4구역 맵 진입, 다시하기도 4구역 | — |

| M2 | 주먹·점프 | 받는 사람을 쳐서 날려 보내며 완료, 도둑도 주먹으로 회수 | M1 |
| M3 | 구역 순환 주문 | 가게 12·문 32 중에서 만들어지는 주문, 거리별 보상 | M1·M2 |
| M4 | 하루 반복·경제 | 생활비 → 인라인 구매 → 다음 날 → 일괄 상환 엔딩, 저장·이어하기 | M3 |
| M5 | 사건 체계 전환 | 수령 전에는 오브젝트만, 배달 중에는 콜마다 켜지는 트리거와 연쇄 | M3 |
| M6 | 이삿짐 트럭 | 1일차 150초 뒤의 큰 사건, 전조 → 3막 → 종료 | M5 |
| M7 | 주소 오입력·요청 팁 | 문 앞에서 목적지가 바뀌는 콜, 팁 요청 1종 | M3 |
| M8 | 통합·조정 | 첫날부터 엔딩까지 한 판, 실행 빌드 | 전부 |

M4는 M5보다 먼저 한다. 사건이 적어도 엔딩까지 도는 반복을 먼저 완성하고, 그 위에 사건을 더해 시간 손해를 체감으로 조정한다. M7은 M3 이후 언제든 끼워 넣을 수 있다.

각 단계는 **코드 작성 → `unity recompile` 컴파일 확인 → 에디터 API로 씬 반영·저장 → 사용자 플레이 확인 절차 제공**으로 끝낸다. Play 모드 진입과 자동 플레이는 사용자가 요청할 때만 한다.

## M0. 본 씬 이전

**작업**

- 빌드 목록에 `Assets/_Game/Scenes/FourDistrictPrototype.unity`를 추가하고, 게임 씬 순서를 `TitleScene → FourDistrictPrototype`으로 둔다. 빌드 목록은 에디터 API로 변경한다.
- `SceneController`의 `ESceneType.GameScene`이 4구역 씬을 가리키게 한다. 정산의 다시하기(`DeliverySession.ReplayDay`)도 같은 경로를 탄다.
- 4구역 씬에 남아 있는 비활성 구형 사건 루트(`TrafficPilotWorld`, 구형 `IncidentTrigger`, `TimedIncidentScheduler`)는 그대로 둔다. M5에서 정리한다.
- `ReplayDay` 안의 주석이 깨져 보이는 문제를 정리한다. 실제로는 CP949로 저장된 파일이어서, 내용은 그대로 두고 UTF-8로 변환한다.

**완료 기준**: 타이틀에서 시작하면 4구역 씬의 C 구역 집 앞에서 시작한다. 정산 후 다시하기를 눌러도 4구역 씬으로 돌아온다. `GameScene`은 파일과 내용이 그대로다.

## M1. 시간·콜 흐름 전환

**`DeliverySession`**

- 배달 타이머 시작을 `TryAcceptOrder`에서 **첫 `TryPickup`**으로 옮긴다. 재수령으로 타이머가 다시 시작되면 안 되므로 `orderDeadline`이 이미 정해졌는지 확인한다. 이 계산은 `DeliveryResult`의 소요 시간에도 그대로 쓴다.
- 하루 시작: 집 앞 출발 트리거에서 처음 벗어날 때 `dayStartedAt`을 정한다. 그 전에는 하루 시간이 흐르지 않는다. 트리거가 없는 씬에서는 지금처럼 시작하는 시점을 기준으로 한다.
- 콜 화면 상태 `IsCallOpen`을 추가한다. 주문이 없을 때 1번으로 열고, 열려 있는 동안 `Time.timeScale = 0`으로 둔다. 지도(`IsMapOpen`)는 별도로 남겨 시간이 흐르게 한다.
- 배달 완료 뒤 지도·콜을 자동으로 열지 않는다(`IsMapOpen = true` 제거). 시작 시 지도를 열어 두는 기본값도 끈다.
- 후보 수 `candidateCount`를 2로 바꾸고 상한도 2에 맞춘다. 체험판 시작값이며 설정으로 남긴다.
- `CanMove`에 `IsCallOpen`을 반영한다. 일시정지·정산과 콜 화면이 겹칠 때는 일시정지 > 콜 > 지도 순으로 Esc를 처리한다.

**입력 (`RiderMotor`)**: `Digit1` 콜 열기, 콜 화면에서 `Digit1`·`Digit2`로 수락, Esc로 닫기. 마우스 클릭 수락도 유지한다.

**UI**

- `GameHud`의 주문 카드에 쓰던 패널을 콜 화면 2칸으로 바꾼다. 칸마다 가게·구역 → 문·구역, 보상, 제한시간을 보여준다. 수락 전 표시 문구는 "수령 순간 시간 시작"으로 바꾼다.
- `DeliveryDayHud`의 하루 시계를 해시계로 바꾼다. 원형 `Image`(fill)와 해 아이콘을 쓰고 숫자는 감춘다. 배달 타이머는 숫자로 유지하되, 수령 전에는 "수령하러 가는 중"을 보여준다.
- `DeliveryMapView`의 후보 마커는 콜 화면 상태에서만 강조한다.

**설정**: `DeliveryDaySettings`에 하루 길이 600초, 후보 수 2를 넣는다.

**완료 기준**: 수락 후 가게로 가는 동안 배달 타이머가 줄지 않는다. 콜 화면을 연 동안은 시간이 멈추고, 지도를 연 동안은 시간이 흐른다. 마감 이후 새 콜을 열 수 없고, 수령 전 주문도 끝까지 진행한 뒤 한 번만 정산한다.

## M2. 주먹·점프

**입력**: `F`와 마우스 왼쪽 클릭으로 주먹, 스페이스로 점프. 콜·지도·일시정지 중에는 둘 다 막는다.

**주먹 판정 (`RiderMotor`)**

- 0.35초 쿨다운을 둔다. 플레이어 앞 1.2m 지점에 반경 0.9m `OverlapSphereNonAlloc`을 쓰고, 배열은 미리 할당한다.
- 맞은 대상에서 `IPunchable.ReceivePunch(Vector3 direction)`을 찾는다. 받는 사람·도둑·행인·소품이 같은 동작을 공유하므로 이 작은 인터페이스는 실제로 필요하다.
- 사고로 날아가는 중이나 기절 중에는 주먹을 막는다.

**받는 사람 (`DeliveryResident`)**

- `OnCollisionEnter` 전달을 제거하고 `ReceivePunch`에서 `session.TryDeliver(this)`를 호출한다. 성공했을 때만 큰 충격으로 날려 보낸다.
- 실패한 타격(음식 없음, 다른 사람)은 작게 밀리기만 한다.
- 날아간 뒤 3초가 지나거나 복귀 반경을 넘으면 집 위치로 복귀한다. 날아가는 중의 복귀 반경 판정이 연출을 끊지 않도록 비행 시간 동안은 판정을 미룬다.

**도둑 (`FoodThief`)**: 주먹으로 `TryRecoverFood`를 호출한다. 기존 충돌 회수는 M2에서 제거하되, 도둑을 놓쳤을 때 재수령으로 넘어가는 흐름은 그대로 둔다.

**점프**: 접지 상태에서만 수직 속도를 준다. 기존 `TryGround`를 재사용한다. 착지 판정은 맨홀·수박의 `groundedForHazards`와 섞이지 않게 한다.

**UI**: 목적지 안내 문구를 "받는 사람을 주먹으로", "도둑을 주먹으로"로 바꾼다.

**완료 기준**: 행인을 치거나, 음식 없이 치거나, 몸으로 부딪혀서는 완료되지 않는다. 받는 사람을 연속으로 쳐도 보상은 한 번만 들어온다. 날아간 받는 사람은 복귀하고, 플레이어는 다음 콜로 넘어갈 수 있다.

## M3. 구역 순환 주문

지금은 주문이 `DeliveryOrderRoute` 6개로 고정되어 있고, 4구역 맵에는 가게 12·문 32 위치가 이미 있다(`Shop_01~12`, `Door_01~32`, 구역 정보는 `district_geometry.json`의 `zone`).

**데이터**

- `DeliveryPoint` 컴포넌트를 둔다. 필드는 구역(A~D), 접근 지점, 표시 이름이다. 가게와 문 오브젝트에 에디터 설치기로 붙인다.
- 큰길 거리표: `Tools/build_district_geometry.py`를 확장해 원본 노드 그래프에서 **큰길만 쓰는 최단 거리**(가게 12 × 문 32)를 계산하고 `MapLayout/route_distance.json`으로 내보낸다. 에디터 설치기가 이를 `DeliveryRouteTable` ScriptableObject로 가져온다. 런타임 경로 탐색은 만들지 않는다.
- `DeliveryEconomySettings`(ScriptableObject)에 아래 값을 둔다.
  - 보상 등급: 3,000 / 4,500 / 5,500원, 경계 350m·470m, 최소 배달 거리 300m
  - 지각 비율 60%
  - 제한시간 공식 계수: 거리 ÷ 달리기 속도 × 1.5 + 25초
  - 가게·음식·손님 이름 목록

**주문 생성 (`DeliverySession.FillCandidates` 교체)**

- 출발 구역 = 마지막으로 배달을 끝낸 구역. 첫 콜은 집이 있는 C 구역에서 받는다.
- 가게는 출발 구역에서 고른다. 문은 다른 구역에서 고르되, 방금 떠나온 구역은 빼고 최소 거리 미만도 뺀다. 이렇게 2건을 만든다.
- 보상과 제한시간은 거리표와 설정으로 계산해 `DeliveryOrderOffer`에 담는다. 기존 `DeliveryOrderDefinition` 6개는 시험용으로 남기고, `DeliveryOrderOffer`가 정의 없이도 동작하도록 값을 직접 갖게 한다.

**받는 사람**: 문 32곳마다 NPC를 두지 않는다. 받는 사람 1명(`DeliveryResident`)을 수락 시 목적지 문 앞으로 옮기고, 그 문을 집 위치로 삼는다. 묶음 배달이 생기면 그때 늘린다.

**지도**: `DeliveryMapView`가 콜 2건의 가게·문을 표시한다. 고정된 `pickupPoints` 배열 대신 현재 후보와 활성 주문 기준으로 그린다.

**완료 기준**: 같은 가게·같은 문만 반복되지 않고, 배달을 끝낸 구역에서 다음 콜이 나온다. 모든 가게와 문에 달리기로 접근할 수 있다. 4구역 정적 검사를 재사용해 문 32곳 접근 구간을 다시 확인한다. 거리 등급과 보상·제한시간이 콜 화면 숫자와 일치한다.

## M4. 하루 반복·경제·저장·엔딩

**진행 상태 `RunProgress`**: 일차, 현금, 빚, 인라인 보유, 누적 배달 수를 담는 일반 C# 클래스다. 설정 자산과 섞지 않는다. 씬 재시작을 넘어 유지되도록 `SceneController`(이미 씬 전환 뒤에도 남는 싱글턴)가 들고 있게 한다.

**정산 화면 (`DeliveryDayHud` 확장)**

1. 배달별 결과, 오늘 수익
2. 생활비 5,000원 자동 차감. 부족하면 현금 0원으로 두고 부족분만 빚에 더한다.
3. 인라인 8,000원 구매 버튼. 2일차부터 판매하고, 보유 중이면 비활성화한다.
4. 현금이 빚 이상이면 "빚 갚기" 버튼 → 엔딩
5. 다음 날 버튼

**중복 방지**: 생활비와 구매는 정산 1회당 한 번만 적용한다. 정산 화면을 다시 열거나 버튼을 연타해도 같은 결과여야 한다.

**인라인 (`RiderMotor`)**: 보유하면 속도 ×1.6(시험값), 가속을 낮춰 관성을 준다. 제한시간 계산은 달리기 기준을 유지한다.

**저장**: 정산을 끝낸 시점에 `Application.persistentDataPath/save.json`(`JsonUtility`)으로 저장한다. 버전 필드를 두고, 파일이 없거나 읽기에 실패하면 새 게임으로 시작한다.

**타이틀**: 새 게임 / 이어하기 버튼을 둔다. 테스트용으로 시작 일차 1~6 선택을 넣는다(기획서 확정 사항).

**엔딩**: 빚 상환 문구와 누적 일수·배달 건수를 보여주는 화면을 띄운 뒤 타이틀로 간다. 엔딩 뒤에는 저장 파일을 지운다.

**빚 시작값**: 100,000원(미정 항목, 시험값).

**완료 기준**: 현금이 음수가 되지 않는다. 다음 날 인라인이 적용되고 다시 살 수 없다. 재실행 후 이어하기로 같은 일차·현금·빚이 돌아온다. 상환은 한 번만 엔딩으로 간다.

## M5. 사건 체계 전환

**분류 표시**: 접촉형 위험물(`SwingDoorHazard`, `RollingTireHazard`, `GroundContactHazard`)에 `HazardSlot` 컴포넌트를 붙인다. 필드는 아래와 같다.

- 종류: 오브젝트 / 트리거
- 해금 일차
- 일차별 배치 순위(0~1)
- 구역
- 콤보 묶음 번호

**배치·활성화 담당 `HazardPlanner`** (씬에 1개)

- 하루 시작: 오브젝트는 해금 여부와 `OBJ_DAY` 비율(40/55/70/85%, 시험값)로 그날 놓을 자리를 정해 켠다. 하루 내내 유지한다.
- 콜 수락: 트리거를 모두 끄고 일차별 목표 수(5/8/10/13, 시험값)만큼 다시 고른다. 약 70%는 가게 → 문 직선 경로 주변의 큰길·골목 자리에서 고른다. 같은 묶음은 함께 켠다.
- 트리거는 `Stage == Carrying`일 때만 공격을 시작한다. 수령 전에는 보이기만 한다.
- 연쇄 점화: 피격 시 40m 안의 꺼진 트리거 하나를 확률로 켠다(80%, 오브젝트에 맞은 경우 30%). 활성 수 상한을 둔다.

**대표 종류 (첫 완성판)**

- 오브젝트: 맨홀·수박·문(이미 있음) + 소화전(새로 만듦)
- 트리거: 타이어(있음) + 오리 떼·닭(새로 만듦, 기획서상 확정 트리거) + 비둘기 탈취(기존 도난을 원거리 탈취형으로 전환)

**배치 규모**: 회의 기준 80곳 안팎에서 시작한다. 구역마다 큰길 12·골목 8 정도를 두고, 그중 골목 3곳에 묶음을 넣는다. 자리 좌표는 `트리거_수_v5.json` 대신 원본 HTML에서 같은 방식으로 뽑아 `MapLayout/hazard_slots.json`을 만들고, 에디터 설치기가 배치한다.

**`IncidentDirector` 정리**: 4구역 씬에서는 구형 구역 사건 루트를 제거한다(파일은 유지). 대표 도난은 새 체계로 옮긴다. 단일 슬롯 제약은 도난에만 남긴다.

**완료 기준**

- 수령 전에는 오브젝트만 터진다.
- 콜마다 켜지는 트리거가 바뀐다.
- 연쇄 중에도 주문을 끝낼 수 있다.
- 지도·콜 화면·일시정지에서 새 공격이 시작되지 않는다.
- 정산·씬 전환 후 남는 사건 객체가 없다.

## M6. 이삿짐 트럭 (1일차 고정 사건)

**발동 `FixedEventScheduler`**: 하루 시작 150초 뒤, 음식을 들고 배달 중일 때 플레이어 근처 큰길에서 시작한다. 일차와 사건의 대응표는 설정 자산에 둔다. 첫판은 1일차와 5일차에 트럭만 둔다.

**구성 (시험값)**

| 구간 | 시간 | 내용 |
|---|---|---|
| 전조 | 8초 | 트럭 뒷문이 덜컹거림 |
| 1막 | 0~30초 | 박스·의자가 2초마다 떨어짐 |
| 2막 | 30~75초 | 소파·냉장고가 5초마다 떨어짐 |
| 3막 | 75~110초 | 피아노 → 집주인이 자는 침대 |
| 종료 | | 줄어들며 사라짐 |

- 사건 목표: 침대의 집주인을 주먹으로 치면 일찍 끝나고 1,000원(시험값)을 준다. 목표를 놓쳐도 시간이 되면 끝난다.
- 가구는 기존 접촉형 충격 경로(`ApplyContactCrash`)를 재사용한다. 가구 탑승은 첫판에서 제외한다.
- 정리 범위: 사건이 만든 오브젝트만 정리한다. 일반 트리거·도난을 끄지 않는다.

**완료 기준**: 전조를 알아볼 수 있고, 사건 중에도 배달할 수 있다. 끝난 뒤 가구·조작 잠김이 남지 않는다. 정산이나 마감과 겹쳐도 한 번만 정리된다.

## M7. 주소 오입력·요청 사항 팁

**주소 오입력**

- 음식을 들고 문 7m 안에 처음 들어갈 때 15% 확률로 발생한다.
- 같은 구역의 다른 문(60~220m 떨어진 곳)으로 목적지를 바꾸고, 받는 사람을 그 문으로 옮긴다.
- 지도·안내를 갱신한다. 제한시간은 그대로다.

**요청 사항 팁 1종**

- 내용: "음식 받은 뒤 행인과 부딪히지 않기"
- 콜 화면에 미리 보여주고 팁은 1,000원이다(시험값).
- 행인 충돌은 `DeliverySession`이 한 곳에서 기록한다. 완료용 주먹은 실패로 세지 않는다.

**완료 기준**: 목적지가 바뀌어도 한 번에 완료되고, 보상·팁은 각각 한 번만 들어온다.

### M1 구현 기록

- `DeliverySession`

  - `DeliveryRouteTable`(`Settings/RouteTable.asset`): JSON을 그대로 가져온 값이다.

  - 제한시간은 거리 ÷ 6 × 1.5 + 25초를 5초 단위로 올린 값이다.
  - 첫 콜은 C 구역(집)에서 받는다. 배달을 끝내면 그 문의 구역이 다음 출발 구역이 된다.
- 받는 사람: 문마다 NPC를 두지 않고 `Customer` 1명을 수락 순간 목적지 문의 `RecipientStand`(문 앞, 길 쪽을 바라봄)로 옮긴다(`DeliveryResident.AssignHome`).
- 지도: 4구역 씬에서는 가게 표시를 고정 3곳 대신, 열린 콜이나 진행 중 주문의 가게만 이름과 함께 보여준다. 후보 마커는 목적지 문 위치에 놓는다. 옛 씬은 기존 표시를 유지한다.
- 콜 카드: 가게(구역), 손님(구역), 큰길 기준 거리·등급, 정시/지각 보상, 제한시간을 보여준다.
- 씬: `Delivery Rider → Apply Zone Calls (M3)` 설치기(`Editor/ZoneCallInstaller.cs`)로 연결했다. 내용은 거리표·경제 자산 연결, 가게 12·문 32(각 문에 `RecipientStand` 생성), 받는 사람 지정, 시작 구역 C.
  - 옛 고정 주문용 `Customer_North`·`Customer_South`는 문 앞에 서 있으면 받는 사람과 헷갈리므로 이 씬에서 비활성화했다(삭제 아님).
  - 설치기 안의 저장 뒤에도 씬이 다시 저장 안 된 상태로 표시되어 `save_scene`으로 한 번 더 저장했다.
- 확인: 컴파일 오류·경고 0, 콘솔 오류 0. 가게 12·문 32 참조 누락 0. 플레이 미검증.

### M4 구현 기록

- `RunProgress`(`Scripts/Economy/RunProgress.cs`): 일차·현금·빚·인라인 보유·누적 배달 수를 담는다. 정산 규칙도 여기서 한 번만 적용한다(`CloseDay`).
  - 오늘 수익을 현금에 더한 뒤 생활비를 뺀다. 모자라면 현금은 0원이 되고 부족분만 빚에 더한다.
  - 인라인은 정산 때 살 수 있다. 판매 시작 일차 이상, 미보유, 현금 충분이 조건이다.
  - 빚은 전액일 때만 한 번에 갚을 수 있고, 갚으면 엔딩이다.
- 저장: `Application.persistentDataPath/save.json`(`JsonUtility`, 버전 1).
  - 정산 화면에서 "다음 날"이나 "저장하고 타이틀로"를 누르면 다음 날 아침 상태로 저장한다.
  - 하루 도중에 일시정지로 타이틀에 나가면 저장하지 않는다. 이어하기는 그날 아침부터 다시 시작한다.
  - 파일이 없거나 읽기 실패·버전 불일치면 이어하기를 막고 새 게임으로 시작한다. 엔딩 뒤에는 저장 파일을 지운다.
- `SceneController`
  - `Progress`를 씬 전환 뒤에도 유지한다. `StartNewGame(시작 일차, 시작 빚)`과 `ContinueGame()`을 제공한다.
  - 게임 씬을 바로 실행하면 1일차 새 판으로 시작한다.
- `DeliveryEconomySettings`에 시작 빚 100,000·생활비 5,000·인라인 8,000원(2일차부터 판매)·인라인 속도 ×1.6·가속 ×0.6을 추가했다. 모두 시험값이다.
- `RiderMotor.EquipInline`: 인라인을 가지고 시작한 날은 속도와 가속을 바꾼다. 제한시간 계산은 그대로다.
- 정산 화면(`DeliveryDayHud`)
  - 왼쪽은 배달 목록, 오른쪽은 수익·생활비·부족분 빚·보유 현금·남은 빚이다.
  - 버튼: 인라인 구매, 빚 한 번에 갚기, 다음 날(N일차), 저장하고 타이틀로.
  - 상환하면 같은 패널이 엔딩 화면으로 바뀐다(청산 일수, 누적 배달 수). 엔딩의 버튼은 타이틀로 하나뿐이다.
  - HUD 오른쪽 위에 "N일차 · 인라인 · 보유 · 빚"을 표시한다.
- 타이틀(`TitleUI`): 새 게임·이어하기·게임 종료 버튼. 숫자 1~6으로 새 게임 시작 일차를 고른다. 이어하기는 저장 파일이 있을 때만 누를 수 있다.
  - 옛 안내 문구 "걸어서 출발하고, 부딪혀 전달하세요."는 시작 일차 표시로 바꿨다.
- 씬: `Delivery Rider → Apply Run Loop (M4)` 설치기(`Editor/RunLoopInstaller.cs`)로 4구역 씬 정산 패널(Ledger·BuyInline·Repay)과 TitleScene(ContinueButton·StartDay)에 적용했다. 두 씬 모두 저장했고, 에디터에는 TitleScene을 열어 두었다.
- 시작 일차는 지금은 일차 숫자와 인라인 판매 여부에만 영향을 준다. 일차별 해금·사건은 M5·M6에서 연결한다.
- 확인: 컴파일 오류·경고 0, 콘솔 오류 0. 플레이 미검증.

### M5 구현 기록

- 자리 데이터
  - `Tools/build_hazard_slots.py <HTML>`가 체험판 길 그래프 위에 자리 80곳을 정해 `Docs/MapLayout/hazard_slots.json`을 만든다. 시드 13으로 매번 같은 결과가 나온다.
  - 체험판은 실행할 때 무작위로 450곳을 깔기 때문에 위치를 그대로 옮기지 않았다. 규칙만 따른다: 일반 도로 노드에 두고, 가게·문·집에서 12m 이상, 자리끼리 14m 이상 떨어뜨린다.
  - 결과: 구역마다 20곳, 큰길 56·골목 24, 콤보 묶음 10개(맨홀 슬라롬 2, 문→맞은편 맨홀 2, 골목 맨홀 징검다리 3, 골목 수박 미끄럼→맨홀 3).
  - 각 자리에는 그 옆 7m 안을 지나는 콜 경로(가게×문)가 기록돼 있다. 큰길 최단 경로와 전체 최단 경로를 모두 본다. 경로가 하나도 지나지 않는 자리는 1곳뿐이다.
- 종류와 해금 (전부 시험값)
  - 오브젝트: 맨홀 14·수박 좌판 10·문 6·소화전 6. 모두 1일차부터 나온다. 맨홀·수박·문은 일차별 비율(40/55/70/85%)만큼만 놓인다.
  - 트리거: 오리 떼 12·닭 12(1일차), 타이어 10·비둘기 탈취 10(2일차).
- 런타임
  - `HazardSlot`: 종류, 역할(오브젝트/트리거), 해금 일차, 배치 순위, 구역, 골목 여부, 콤보 번호, 경로 목록을 가진다.
  - `HazardPlanner` 하루 시작: 그날 놓을 오브젝트를 정한다. 오브젝트는 수령 전에도 작동한다.
  - `HazardPlanner` 콜 수락: 트리거를 모두 끄고 일차별 수(5/8/10/13)만큼 다시 고른다. 순서는 아래와 같다.
    1. 해금된 종류마다 50% 확률로 경로 위 1곳을 먼저 켠다.
    2. 경로 위에서 목표의 70%까지 채운다.
    3. 나머지는 맵 어디서나 채운다.
    - 한 종류는 전체의 1/4(최소 2곳)까지만 켠다. 콤보 묶음은 조금 먼저 뽑히고 함께 켜진다.
  - 트리거는 켜져 있어도 음식을 받은 뒤에만 공격을 시작한다(`StrikeAllowed`).
  - 연쇄 점화: 실제로 맞으면 40m 안의 꺼진 트리거 하나가 80% 확률로 켜진다(오브젝트에 맞았을 때 30%). 콜당 목표보다 4곳 넘게는 늘리지 않는다.
  - 기존 문·타이어·맨홀·수박은 `HazardSlot`이 허락할 때만 공격을 시작한다. `RiderMotor.HazardHit` 이벤트가 연쇄 점화에 쓰인다.
- 새 종류
  - 소화전(`GroundHazardKind.Hydrant`): 인도 끝에 있다. 다가가면 예고 후 물기둥이 솟고, 닿으면 위로 크게(11) 날아간다.
  - 오리 떼(`CrossingFlockHazard`): 8m 안으로 오면 5마리가 줄지어 길을 건넌다. 닿으면 튕겨 나간다.
  - 닭(`ChaseFlockHazard`): 길가 4마리를 스치면 14초 동안 쫓아와 1.5초마다 쪼아 살짝 밀친다.
  - 비둘기 탈취(`PigeonSnatchHazard`): 음식을 들고 4m 안에 오면 예고 후 음식을 채 간다. 길을 따라 낮게 날아가며, 주먹으로 쳐서 되찾는다. 놓치면 가게에서 다시 받는다(`FoodThief` 재사용).
- 씬: `Delivery Rider → Apply Hazard Slots (M5)` 설치기(`Editor/HazardSlotInstaller.cs`)가 `HazardSlots` 루트를 매번 새로 만든다.
  - 기존 L7·L8 대표 사건(문·타이어·맨홀·수박·도난 구역)은 비활성화했다. 삭제하지는 않았다.
  - 4구역 씬을 저장했고, 에디터에는 TitleScene을 다시 열어 두었다.
- 정적 확인: 자리 80곳 생성, 참조 누락 0. 타이어 10개의 굴러가는 길에 지형·건물 충돌 없음. 컴파일 오류·경고 0, 콘솔 오류 0. 플레이 미검증.
- 남은 것
  - 소리 지르기(Q)로 오리·닭 흩기는 미구현이다.
  - 비둘기 도주 경로가 교차로 건물에 막힐 수 있다. 막히면 35초 뒤 재수령으로 넘어간다.
  - 트리거 수(일차별 5~13)는 체험판 값이다. 자리가 80곳뿐이라 4일차부터는 트리거 44곳 중 13곳(약 30%)이 켜져 체험판보다 촘촘하다. 플레이 후 조정이 필요하다.
