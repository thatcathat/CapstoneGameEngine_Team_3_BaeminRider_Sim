# 4구역 맵 대표 사건 구간

- 적용일: 2026-10-14
- 씬: `Assets/_Game/Scenes/FourDistrictPrototype.unity`
- 씬 루트: `RepresentativeIncidents`
- 상태: 코드 검토, Unity 컴파일, 배치·저장과 정적 참조/경로 검사 완료. 실제 플레이 미실행.

## 배치

| 구간 | 구성 |
|---|---|
| C 구역 L7 골목 | 기존 문을 새 위치에 복제하고, 실제 문 피격 시 출발하는 타이어를 연결 |
| C 구역 L8 골목 진입부 | 대표 도난 구역과 지형에 맞춘 39개 도주 경유점 |
| L8 진행 방향 20m 지점 | 맨홀: 약 X=-24.84, Y=1.93, Z=109.36 |
| 맨홀에서 진행 방향 6m 뒤 | 수박: 약 X=-27.12, Y=1.83, Z=103.81 |

맨홀·수박 구간은 약 1.7%의 완만한 내리막이다. 가까운 출입구까지의 수평 거리는 각각 약 30m, 36m다. 수박의 폭은 2.1m로 4.5m 골목 양옆에 피할 공간을 남겼다. 집 앞과 수령·전달 지점 바로 앞에는 배치하지 않았다. 기존 `TrafficPilot`은 수정하지 않았고, 새 맵의 비활성 원본도 보존했다.

## 맨홀과 수박

`GroundContactHazard`가 맨홀과 수박의 실제 접촉·종료·재장전을 담당한다. 예고용 거리와 피격용 BoxCollider를 구분하며 플레이어 CapsuleCollider와의 겹침으로 피격을 판정한다. 물리적인 벽처럼 플레이어를 가두지 않도록 접촉 볼륨은 Trigger다.

- 맨홀: 2.8m 접근 → 0.7초 점멸 예고 → 0.6초 분출 → 종료. 분출 중 접촉해야 전방 6m/s·위쪽 4.5m/s의 속도 변화가 적용된다. 지면 접선과 법선을 발사 방향에 반영한다. 회차당 접촉은 한 번만 소비한다.
- 수박: 지면에 닿은 상태에서 과육 영역을 밟으면 2.2초 미끄러진다. 공중 통과만으로 미끄러짐을 예약하거나 강제로 적용하지 않는다. 착지 지점을 피하면 연쇄도 피할 수 있다.
- 미끄러짐: 방향 조작을 남기되 가속을 제한한다. 경사 방향 가속을 반영하고 최고 속도를 8m/s로 제한한다. 종료 후 기존 이동 코드로 돌아간다.
- 이번 두 오브젝트의 재장전: 종료 후 10초 경과 + 플레이어가 4m 이상 이탈. 이 값은 대표 시범의 시험값이며 HTML의 모든 오브젝트에 동일한 정책을 확정한 것이 아니다.

임시 표현은 맨홀 뚜껑·점멸판·분출 기둥, 수박 과육·껍질이다. 최종 파티클·애니메이션·오디오 자산은 이번 범위가 아니다.

## 이동 상태와 연쇄

`RiderMotor`는 지면 접촉을 별도로 확인한다. 접촉 사고의 최소 회복 시간이 끝나도 공중에 있으면 낙하를 유지하며, 착지 후 회복한다. 예상 밖의 공중 정체에는 추가 6초의 회복 상한과 기존 추락 복귀가 있다. 일반 차량의 재피격 방지는 실제 회복 후에도 최소 1초 유지한다.

맨홀 발사 후 착지 위치에 수박이 있으면 서로 다른 위험물의 연쇄로 미끄러짐을 시작할 수 있다. 기존 0.35초 최소 피격 간격과 8초 연쇄 집계를 재사용한다. 후속 발사는 미끄러짐을 종료하고 속도를 대체하며, 미끄러짐은 자신이 소유한 상태만 해제한다. 도둑 추격 종료가 접촉 사고나 미끄러짐을 임의로 종료하지 않는다.

지도 열림 중에는 새 공격을 시작하지 않고 진행 중 맨홀 예고·분출 및 미끄러짐을 정리한다. 공중 사고는 지도 때문에 순간 정지시키지 않는다. 일시정지에서는 게임 시간과 함께 멈추며, 정산은 timeScale=0에서도 Update로 효과와 접촉 상태를 정리한다. 위험물 비활성화는 자신이 만든 미끄러짐만 해제한다.

## 도난과 동시 진행

기존 `TheftChase` 설정을 사용한 도난 구역 1개를 L8 앞쪽에 배치했다. 새 구역만 `preserveActiveIncident`와 `deferWhileMapOpen`을 켰다. 따라서 추격 중 구역을 다시 지나도 기존 사건을 취소하고 도둑을 다시 만들지 않으며, 지도를 보고 있을 때 새 도난을 시작하지 않는다. 지도 안에서 이미 진입했다면 닫은 뒤 밖으로 나갔다가 재진입해야 한다.

맨홀·수박·문·타이어는 `IncidentDirector.TryStart`와 음식 상태 변경을 호출하지 않는다. 음식 회수는 기존 도둑 접촉 방식이며, 사고 회복 중에는 기존 이동 제한에 따라 즉시 회수되지 않을 수 있다. 도둑을 놓치거나 시간이 끝나면 기존 음식점 재수령 경로를 유지한다. 이번 도난은 기존 구역 진입 방식이며, 도둑의 실제 탈취 접촉 방식으로 전환한 것은 아니다.

## 확인 결과

- Unity 컴파일 오류 없음, 씬 저장 완료, 미저장 변경 없음, Play 모드 미진입.
- 활성 대표 구성: 문 1개, 타이어 1개, 맨홀 1개, 수박 1개, 도난 구역 1개.
- 검사한 세션·문·타이어·Director 필수 참조 누락 없음, 문→타이어 연결 확인.
- 새 타이어 경로 64개 샘플에서 반경 0.55m 충돌체 겹침 없음.
- 도둑 경유점 39개에서 캡슐 공간을 검사해 고정 충돌체 겹침 없음. 이는 실제 도둑 이동이나 동적 회피 확인이 아니다.
- 제작 요청은 연결 서버의 5초 제한으로 시간 초과를 반환했으나, 후속 조회에서 생성·저장 완료를 확인했다.

## 사용자 확인 순서

1. 새 맵의 C 구역 L7에서 문을 피했을 때 타이어가 출발하지 않는지 확인한다.
2. L8에서 맨홀 예고를 보고 옆으로 벗어나 피한다. 분출 밖에서는 발사되지 않아야 한다.
3. 맨홀을 밟아 날아간 뒤 수박 쪽에 착지한다. 미끄러짐 중 방향 조작, 최고 속도 제한, 정상 조작 복귀를 확인한다. 같은 수박에서 계속 다시 맞으면 안 된다.
4. 음식을 운반하며 L8 도난 구역에 들어간 뒤 사건 구간을 통과한다. 추격이 유지되는지, 회수 또는 음식점 재수령 후 배달 가능한지 확인한다.
5. 지도·일시정지·정산 전환, 10초 이상 경과 후 충분히 벗어났다가 재진입을 확인한다.

위 항목의 실제 플레이 체감과 연쇄 성공률은 아직 확인하지 않았다. 이후 주문별 활성화·일차별 밀도를 만들기 전에 이 대표 구간의 피할 시간과 착지 위치를 조정한다.
