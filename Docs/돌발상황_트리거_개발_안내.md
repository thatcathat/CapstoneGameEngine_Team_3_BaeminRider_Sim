# 돌발상황 트리거 — 9번

## 구현 범위

- 구역 진입 → 조건 검사 → 확률 판정 → 가중치 선택 → 사건 실행 → 회복 → 공통 보호 시간.
- `IncidentDirector`가 주요 사건을 한 번에 하나만 실행한다. 기본 보호 시간은 종료 후 8초다.
- `IncidentTrigger`는 연결된 설정 목록 중 하나를 선택한다. 한 항목만 연결하면 고정 종류다.
- 한 번 진입하면 한 번만 판정한다. 확률 실패나 사건 진행 중 진입도 구역 내에서 재시도하지 않는다.
- 트리거별 기본 발생 확률 1, 대기 시간 20초, 하루 최대 3회. 실제 시작한 사건만 횟수를 차감한다.
- 설정 자산에는 실행 상태를 저장하지 않는다. 다음 씬 시작 시 횟수와 대기 상태가 초기화된다.
- 첫 사건은 경고 후 구역에 남아 있으면 튕겨 나가고 잠시 조작할 수 없는 사고다. 차량 모델·차량 AI는 아직 없다.
- 경고는 0.8초이며 구역 밖으로 벗어나면 회피한다. 주황색 바닥은 위험 범위를 보여주는 프로토타입 표시다.
- 지도에서도 사건 시간과 물리는 흐른다. 일시정지에서는 함께 멈춘다. 사고 중 수령·전달은 불가하고 회복 후 가능하다.
- 주문 시간은 초기화하지 않는다. 영업 종료 후 마지막 주문에도 작동한다. 정산·씬 종료 및 필수 주문 조건 상실 시 사건을 정리한다.

모든 수치는 테스트 시작값이며 확정 밸런스가 아니다. 도난·시간 주기 트리거는 후속 단계다.

## 씬과 설정

`GameScene > Incidents`

| 구역 | 중심 좌표 | 목록 |
|---|---|---|
| SouthRoadCrash | (0, 1.5, -3) | CrashMild 고정 |
| EastRoadCrash | (14, 1.5, 4) | CrashMild / CrashStrong 동일 가중치 |

구역 크기는 4×3×4. 주문이 있는 상태에서만 기본 사고가 발생한다.
`Assets/_Game/Settings/Incidents/`에서 충격, 경고·회복 시간, 주문·음식 필수 조건을 변경한다.

## 구역 추가 방법

1. 기존 사고 구역을 복제해 원하는 위치로 옮긴다.
2. `IncidentTrigger > Events`에 원하는 설정 자산을 연결한다. Weight는 후보 간 상대 비중이다.
3. Chance, Cooldown Seconds, Max Per Day를 조절한다.
4. Box Collider 크기를 조절한다. 바닥 표시 크기도 함께 맞춘다. 최종 아트 단계에서는 바닥 표시를 제거해도 된다.
5. 구역의 파란색 Z축이 충격 방향이다. 별도 Transform을 Impact Direction에 지정해도 된다.

같은 사고의 변형은 Project 창에서 Crash 설정 자산을 복제한다. 동작이 다른 사건은 `IncidentDefinition`을 상속한 설정 타입의 `Execute`를 구현한다. 실행 중 생성한 객체는 해당 실행의 `try/finally`에서 정리한다. 주문 상태 변경은 DeliverySession의 명시적인 메서드로 요청하며 사건 코드가 보상을 직접 지급하지 않는다.

메뉴 `Delivery Rider > Install Incident Zones`는 누락 요소 설치용이다. 기존 구역의 위치·목록·수치와 기존 설정 자산의 수치는 덮어쓰지 않는다.

## 직접 플레이 확인

1. 주문을 수락하고 남쪽 도로의 주황색 구역으로 진입한다. 경고 후 머무르면 충격, 회복 후 이동이 가능해야 한다.
2. 다시 진입할 때 경고 직후 밖으로 빠져나와 회피 안내를 확인한다. 재발동 대기와 하루 횟수 제한에 유의한다.
3. 사고 중 M으로 지도를 열고 닫아도 충격과 회복 시간이 이어지는지 확인한다. Esc 일시정지 중에는 멈춰야 한다.
4. 음식 수령 후 사고가 나도 주문과 음식이 유지되고, 회복 후 고객 충돌로 정상 전달되는지 확인한다.
5. 구역에 계속 서 있는 동안 재발동하지 않는지, 다른 구역에서도 사건 중복이 차단되는지 확인한다.

자동 Play 모드 진입, 입력 시뮬레이션 및 화면 캡처는 수행하지 않는다.
