# 주문·하루 타이머와 보상·정산 (7~8번)

## 동작

- GameScene 시작부터 하루 제한 시간이 흐른다. 기본값은 300초(5분)다.
- 주문은 수락한 순간부터 해당 주문의 제한 시간이 흐른다. 음식 수령까지 걸린 시간도 포함한다.
- 주문 마감 시각 이내 전달하면 정시 보상, 마감 시각을 넘겼으면 지각 보상을 한 번 지급한다. 시간이 지나도 주문을 포기하거나 실패 처리하지 않는다.
- 수락 시 제한 시간과 보상 값을 확정한다. 이후 설정 자산을 바꿔도 진행 중 주문의 판정과 이미 완료된 기록은 바뀌지 않는다.
- HUD 오른쪽에 하루 시간, 주문 남은 시간 또는 지각 초과 시간, 보유 금액을 표시한다.
- 지도를 열어도 시간이 흐른다. Esc 일시정지에서는 두 시간이 함께 멈춘다.
- 하루가 끝나면 후보를 정리하고 신규 수락을 막는다. 진행 중 주문이 없다면 즉시 정산한다.
- 진행 중 주문이 있다면 ‘영업 종료 / 마지막 배달’로 표시하고 수령·전달을 끝낼 때까지 계속한다. 초과 근무 중에도 주문 시간과 정시·지각 판정이 유지된다.
- 마지막 주문을 완료하면 보상을 지급한 뒤 정산한다. 정산 화면 자체에서는 돈을 추가 지급하지 않는다.
- 정산에는 총 건수, 정시·지각 건수, 총수익, 활동 시간, 배달별 경로·소요 시간·보상을 표시한다. 기록은 5건씩 이전·다음 페이지로 확인한다.
- 정산 화면에서 타이틀로 돌아가거나 ‘다시 플레이’를 선택할 수 있다. 다시 플레이는 같은 프로토타입을 새로 시작하며 현금과 기록을 초기화한다.

관리비·빚·다음 날 성장·저장·리뷰·팁은 이후 단계다. 현재 보유 금액은 이번 플레이에서 받은 배달 기본 보상의 합계다.

## 조정 위치

| 설정 | 파일 / Inspector |
|---|---|
| 하루 길이 | `Assets/_Game/Settings/DaySettings.asset` → Duration Seconds |
| 주문 제한 시간 | `Assets/_Game/Settings/Orders/Order_01.asset` 등 → Time Limit Seconds |
| 정시 보상 | 각 주문 자산 → On Time Reward |
| 지각 보상 | 각 주문 자산 → Late Reward |

짧게 확인하려면 Play 전에 하루 길이를 30초, 특정 주문 제한 시간을 5초로 줄일 수 있다. 정시 배달 확인에는 충분한 제한 시간을 사용한다. 확인 후 기존 값으로 복원한다. 별도 자동 플레이나 시간 조작용 테스트 기능은 추가하지 않았다.

## 사용자 확인 순서

1. 주문 수락 즉시 주문 시간이 감소하고 수령 후에도 초기화되지 않는지 확인한다.
2. 지도에서는 시간이 흐르고, 지도를 닫은 뒤 Esc로 일시정지하면 두 시간이 멈추는지 확인한다.
3. 정시 배달 후 해당 설정의 정시 보상이 보유 금액에 한 번만 더해지는지 확인한다.
4. 주문 마감까지 기다렸다가 배달한다. 지각 초과 시간이 표시되고 지각 보상을 받는지 확인한다.
5. 주문을 수락하지 않은 상태에서 하루가 끝나면 0건 정산이 나오는지 확인한다.
6. 음식 수령 전에 하루가 끝나도록 한 뒤 수령·전달할 수 있는지 확인한다. 마지막 배달 뒤 새 후보 대신 정산이 나와야 한다.
7. 영업 종료 후 지도에서 새 주문을 수락할 수 없는지 확인한다.
8. 정산 총수익이 배달별 보상의 합과 같은지, 화면에서 기다려도 금액이 늘지 않는지 확인한다.
9. ‘다시 플레이’ 후 시간이 정상적으로 흐르고 금액·기록이 0부터 시작하는지 확인한다.

실제 플레이 확인은 사용자가 수행한다. 정시·지각 판단은 표시된 정수 초가 아니라 내부 마감 시각을 기준으로 하며, 시각이 같으면 정시다.

## 제작 확인

GameScene에 DaySettings, 타이머 HUD, 정산 화면과 버튼 참조를 연결하고 저장했다. 에디터에서 컴파일 실패 없음과 Play 모드 미실행을 확인했다. 자동 플레이·화면 캡처·입력 시뮬레이션은 수행하지 않았다.
