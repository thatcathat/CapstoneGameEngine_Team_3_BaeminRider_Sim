# 4구역 지형 시범 구현

- 적용일: 2026-10-14
- 씬: `Assets/_Game/Scenes/FourDistrictPrototype.unity`
- 상태: Unity 컴파일·생성·저장과 정적 참조/충돌 여유 확인 완료. 실제 플레이 미실행.
- 처음에는 `TrafficPilot` 씬을 복사해 만들었다. 2026-10-14 정리에서 `TrafficPilot`·`GameScene`과 이 씬 안의 꺼진 옛 오브젝트, 생성기 `FourDistrictInstaller`를 삭제했다. 지형 데이터 읽기는 `Editor/DistrictLayout.cs`가 맡는다. 생성기는 git 커밋 `9bc1eed`에 있다. (2026-10-14 M0에서 빌드 목록에 추가하고 본 게임 씬으로 지정했다.)

## 구현 범위

HTML 원본 좌표의 큰길 10개(폭 8/10m), 골목 12개(폭 4.5m)를 반영했다. 큰길 양옆에는 각 3m의 보행 포장을 표시하고, 도로 폴리라인 사이의 짧은 연결은 원본 노드 그래프를 사용했다. 골목에는 차량 차로를 만들지 않았다.

지면은 1m 격자의 공유 높이 데이터로 만든 8개 연결 메쉬다. 도로·보도·골목은 같은 지면에 포장 텍스처로 구분하여 연결부에 별도 연석이나 겹친 충돌체가 생기지 않게 했다. 아직 입체 연석·차선 도색·상세 건물·공원 조경을 완성한 맵은 아니다. 구역 색과 간단한 건물 블록, 출입구 표식으로 구성한 지형 시범이다. 주변 비포장 지면도 이동 가능하며 도시 블록 전체를 건물로 막은 상태가 아니다.

원본 가게 12곳·배달 문 32곳·집 1곳의 위치를 만들었다. 원본의 차도 안쪽 표식을 보도 쪽으로 2.5m 이동하여 접근 지점으로 사용한다. 건물 블록은 도로와 보도에서 여유가 있는 위치만 생성한다. 이 45곳 모두가 새 주문으로 등록된 것은 아니다.

기존 음식점 3곳을 `Shop_01`(A), `Shop_03`(B), `Shop_08`(C)에 연결하고, 고객 3명을 `Door_25`(D), `Door_17`(C), `Door_01`(A)에 연결했다. 기존 6개 주문의 수령·전달 참조와 보상·타이머 규칙을 유지했다. 맵이 커졌으므로 제한시간과 하루 길이는 실제 플레이 후 별도로 조정해야 한다. 현재 수치가 전체 맵에 맞춰 조정됐다는 뜻은 아니다.

플레이어는 C 구역 집 앞에서 시작한다. 지형 경사 추종을 켰으며, 기존 지도 배경과 월드 표시 범위도 새 지형에 맞췄다. 지도에 추가한 모든 출입구가 주문 마커로 표시되는 것은 아니며 활성 주문 표시는 기존 방식이다.

## 고도와 평탄화

기존 0~12m 경사면은 초기안이었다. 가까운 교차로·가게 입구의 높이차를 그대로 유지하면 짧은 연결부가 급경사가 되므로, 인접한 평탄 지점의 높이를 먼저 조정하고 전체 경사를 제한했다.

| 항목 | 이번 생성 결과 |
|---|---|
| 지면 범위 | 가로 516m × 세로 458m, 원본 길 바깥 여유 포함 |
| 높이차 | 약 5.433m |
| 전체 지면 최대 경사 | 6.8% (약 3.89도), 모든 격자 삼각형 기준 |
| 평탄 영역 | 교차로·출입구 주변을 병합한 58개 영역 |
| 평탄 내부 | 격자 경계 여유 1m를 제외한 내부 높이 편차는 계산 오차 수준 |

실제 동네 고도를 측량한 결과가 아니라 게임용 제안이다. 높이 제한은 도로 평균값만 검사한 것이 아니라 실제 메쉬에 사용하는 두 삼각형의 기울기 모두를 계산한 결과다. 메쉬 조각은 경계 위치·높이·노멀을 공유한다. 입구에는 별도 계단을 넣지 않았다.

## 교통과 사건

일반 차량 3대를 B1 대표 구간 2대, B6 대표 구간 1대로 연결했다. 두 구간은 교차로에서 18m 물러난 곳에서 회차하므로 이번 씬에 새 다중 교차로 예약망을 만들 필요가 없다. 앞차·장애물 감지·경사 감속은 기존 코드를 사용한다. 전체 10개 큰길을 순환하는 교통망, 교차로 신호, 회전 교통은 후속 범위다.

문·타이어·기존 사건 구역은 `TrafficPilot`에 그대로 남아 있다. 새 씬의 복사본에서는 옛 좌표에 있는 `TrafficPilotWorld`, `DoorHazardPilot`, `TireHazardPilot`, 기존 `IncidentTrigger`와 시간 사건 스케줄러를 비활성화했다. 넓어진 지형에 맞춘 사건 배치와 추격 경로를 만들기 전까지 새 씬에서 잘못 작동하지 않도록 한 조치다. 사건 기능을 프로젝트에서 삭제한 것은 아니다.

## 확인 결과와 남은 확인

- Unity 에디터 컴파일 오류 없음, 새 씬 저장 완료, 미저장 변경 없음, Play 모드 미진입.
- 도로 기준선 22개, 평탄 영역 58개, 목적지 위치 45개, 지면 MeshCollider 8개, 활성 차량 3대.
- 기존 주문 6개의 정의·수령지·고객 참조 누락 0개, 씬 전체 누락 스크립트 0개.
- 차량 차로를 1m 간격의 566개 지점에서 차체 크기와 여유 폭으로 검사: 다른 차량을 제외한 장애물 겹침 없음.
- 활성 캐릭터의 초기 캡슐과 다른 충돌체의 유의미한 관통 없음.
- 45개 출입구에서 길 쪽으로 8m 접근 구간을 총 405개 위치에서 캡슐로 검사: 지형·건물 등의 고정 장애물 없음. 동적 인물·차량은 이 검사에서 제외했다.
- 생성 요청은 서버의 5초 응답 제한을 넘어 시간 초과를 반환했지만, 후속 조회에서 최종 씬 생성·저장을 확인했다. 이를 게임 컴파일 오류로 취급하지 않는다.

정적 배치 확인은 실제 입력을 통한 보행·교차로 통과·수령·전달·차량 회차 검증을 대신하지 않는다. 사용자는 현재 열린 `FourDistrictPrototype`에서 집 출발 → 지도와 실제 길 비교 → A/B/C 수령지와 A/C/D 고객 접근 → 언덕 양방향 이동 → B1/B6 차량 정지·재출발 순서로 확인할 수 있다. 2026-10-14부터 이 씬이 본 게임 씬이다. 타이틀 시작과 정산의 다시 배달하기 모두 이 씬으로 이동한다.

## 동네 건물 (2026-10-14)

`Assets/_Game/Prefabs/Map.prefab`의 집 463채(실제 동네를 본뜬 맵)를 4구역 지형에 맞춰 배치했다. Map 프리팹 원본은 바꾸지 않았다.

- 좌표 맞춤: 4구역 맵은 체험판이 실제 길을 단순화하고 키운 것이다. 그래서 4구역 큰길 중심선과 Map 프리팹 아스팔트의 거리가 가장 작아지는 변환을 찾았다(챔퍼 거리 탐색).
  - 결과: 4구역 (x, z) = 1.61 × 회전(−4°) × 프리팹 (x, z) + (59.444, 72.086). 중심선 평균 거리는 프리팹 기준 약 3.2m다.
  - 4구역은 단순화된 길이라 완전히 겹치지는 않는다.
- 배치 (`Delivery Rider → Apply Neighborhood Buildings`, `Editor/NeighborhoodBuildingInstaller.cs`): 3단계로 놓고, 집 크기는 원래 크기(×1.0)를 쓴다.
  1. 실제 위치: 변환한 자리에 맞는 집을 그대로 둔다. 125채.
  2. 길가: 큰길·골목 양옆의 빈 곳을 같은 집 모델로 길 쪽을 보게 채운다. 198채.
  3. 블록 안쪽: 큰길로 둘러싸인 플레이 구역 안을 9m 격자로 채운다. 30채.
  - 합계 353채. 크기를 ×1.61로 키우면 블록 안에 들어가는 집이 10채뿐이라 원래 크기를 쓴다.
- 비워 두는 곳 (시험값)
  - 큰길: 폭의 절반 + 인도 3m
  - 골목: 폭의 절반 + 0.8m
  - 가게·문·집 접근점에서 7m, 사건 자리에서 4.5m
  - 기존 가게·문 표시 건물과 소품의 충돌체
  - 지형 밖은 제외한다.
- 집은 그 자리 지형의 가장 낮은 높이에 0.15m 묻어 놓는다. 몸체 BoxCollider는 그대로 두고, 정적 배칭용 Static 플래그를 켰다.
- `NeighborhoodBuildings` 루트는 실행할 때마다 다시 만든다. 사건 자리나 가게 위치를 바꾸면 이 설치기를 다시 실행한다.
- 확인: 컴파일 오류 0, 씬 저장, 위에서 본 배치 이미지로 도로·골목·접근점이 비어 있음을 확인했다. 플레이 미검증(카메라 가림, 건물 사이 끼임, 프레임).

## 도로 (Splines, 2026-10-14)

도로가 지면 텍스처 한 장(1m에 약 4픽셀, 경계를 부드럽게 처리하지 않음, 블록 압축)에 그려져 있어 가까이서 경계가 흐리고 울퉁불퉁했다. 그래서 도로를 Unity Splines 패키지(`com.unity.splines` 2.9.1)의 곡선과 메시로 바꿨다.

- 씬의 `Roads` 루트(`RoadNetwork`) 아래 `Road_<id>` 22개가 있다. 각각 `SplineContainer`와 `RoadSurface`를 가진다.
  - 매듭은 기존 꺾은선의 점이다. AutoSmooth 장력 0.2로 모서리만 살짝 둥글게 했다. 콜 거리·사건 자리·건물이 기존 선을 기준으로 놓였기 때문에 크게 벗어나지 않게 했다.
- 표면(보기 전용, 충돌체 없음. 플레이어는 지형 충돌체 위를 걷는다)
  - 큰길: 인도(양쪽 3m), 아스팔트, 가운데 점선(3m 칠하고 3m 비움, 폭 0.22m)
  - 골목: 포장 띠 하나
  - 점들은 지형 위로 투영된다. 높이 순서는 인도 +4cm, 골목 +7cm, 아스팔트 +10cm, 차선 +14cm다. 그래서 교차로에서 아스팔트가 다른 길의 인도를 덮는다. 간격을 1cm로 두면 멀리서 깜빡여서 넓혔다.
  - 점선은 길 끝과 다른 큰길 차도에서 2m 안에서는 그리지 않는다.
- 편집: 씬 뷰에서 `Road_*`의 매듭을 옮기면 그 도로 메시가 바로 다시 만들어진다(도로 하나 약 25ms).
  - 크게 고친 뒤에는 `Roads`의 컴포넌트 메뉴 "Rebuild All Roads"로 전체를 다시 만든다(약 180ms). 이웃 도로의 점선이 새 교차로를 반영하게 하려는 것이다.
  - 도로 메시는 씬 안에 저장된다(정점 약 4만 1천 개, 씬 파일 약 +3MB).
- 지면: `Ground.mat`은 도로를 뺀 구역 색 텍스처(`Art/FourDistrict/DistrictGround.png`, 이방성 필터 4, 고품질 압축)를 쓴다. 지도 UI는 기존 `DistrictSurface.png`를 그대로 쓴다.
- 설치기
  - `Delivery Rider → Apply Road Splines`: `Roads`가 이미 있으면 아무것도 하지 않는다. 손으로 고친 곡선을 지키기 위해서다.
  - `Delivery Rider → Rebuild Road Splines From Data`: 확인 창을 띄운 뒤 데이터로 다시 만든다.
  - 기존 `FourDistrictWorld/RoadCenterlines` 표식은 곡선으로 대체해 삭제했다.
- 곡선을 따르는 것 (2026-10-14): 사건 자리와 동네 건물 설치기는 씬의 `Roads` 곡선을 읽는다(`Editor/RoadPath.cs`, 곡선을 1m 간격 꺾은선으로 샘플링).
  - 사건 자리: `hazard_slots.json`의 각 자리를 자기 도로 곡선의 가장 가까운 점으로 옮긴다. 방향과 폭도 곡선과 도로 표면에서 가져온다. 이번 실행에서 가장 많이 옮겨진 자리는 3.05m다. 어느 콜 경로 옆인지(경로 목록)는 그대로 쓴다.
  - 건물: 도로·인도·골목 여유 판정과 길가 채우기가 곡선을 따른다. 결과는 실제 위치 125채, 길가 203채, 블록 안쪽 22채, 합계 350채다.
  - 길을 고친 뒤에는 `Apply Hazard Slots (M5)` → `Apply Neighborhood Buildings` 순서로 다시 실행한다. 건물이 사건 자리를 피하기 때문이다.
  - 확인: 집 350채 중 도로·인도에 걸친 집 0채. 도로 가운데 사건(맨홀·타이어·오리)과 도로 중심선의 거리는 최대 0.01m. 타이어 굴러가는 길 막힘 0. 씬 참조 오류 0.
- 아직 곡선을 따르지 않는 것: 콜 거리표(`route_table.json`)와 사건 자리의 콜 경로 목록은 체험판 길 그래프 기준이다. 지도 UI 이미지는 기존 그림이다. 길 모양을 크게 바꾸면 거리·보상과 실제 길이 달라질 수 있다.
- 도로 연결과 마감 (2026-10-14)
  - 외곽 위쪽에서 `G` 끝과 `A3` 시작이 30m 떨어져 끊겨 있어서 큰길 `Road_N`(폭 10m)으로 이었다. 연결 도로 목록은 `RoadSplineInstaller`의 `Links`에 있다. "Rebuild Road Splines From Data"로 다시 만들어도 포함된다. 이미 있는 씬에는 `Delivery Rider → Add Missing Road Links`로 빠진 연결만 추가한다.
  - 도로 끝이 다른 도로에 닿는 곳(모서리, T자)에는 둥근 마감(인도·차도 원판)을 덧붙여, 모서리 바깥 인도가 'ㄱ'자로 비던 것을 메웠다.
  - 표면을 폭 방향 약 2m마다 나눴다(마감 원판은 2m 간격 고리). 가장자리에만 정점이 있으면 지형이 볼록한 곳에서 지면이 아스팔트를 뚫고 흰 조각처럼 보였다(N–A3 모서리에서 발견). 표본 약 10만 곳에서 지면이 위로 올라온 곳 0, 가장 작은 틈 3.5cm. 정점은 약 8만 2천 개, 전체 재생성은 약 0.37초다.
  - 이후 사건 자리(80/80), 건물(356채), 교통(교차로 23·막다른 곳 0·차로 70·연결 곡선 156, 전부 도달 가능)을 다시 만들었다.
- 도로 메시는 매듭이나 폭이 실제로 바뀔 때만 다시 만든다. 곡선을 선택만 해도 변경 이벤트가 와서, 예전에는 씬이 저장 안 된 상태로 표시되던 문제를 고쳤다.
- 확인: 컴파일 오류 0, 씬 누락 스크립트·끊어진 참조 0. 씬 뷰 캡처로 도로 경계·교차로·점선을 확인했다. 플레이 미검증.

## 교통 (2026-10-14)

시범 차로 2개와 밴 3대를 큰길 전체를 도는 도로망으로 바꿨다.

- 생성(`Delivery Rider → Apply Traffic Network`, `Editor/TrafficNetworkInstaller.cs`): 씬의 `Roads` 곡선 중 큰길 10개로 만든다.
  - 교차로: 길 끝이 다른 길에 닿는 곳과 두 길이 겹치는 곳에 둔다. 14m 안의 후보는 하나로 합친다. 결과는 21곳이다.
  - 차로: 교차로 사이 구간마다 우측통행 차로를 둘씩 둔다(차도 중심에서 폭의 1/4). 차로는 다른 길 차도 가장자리 + 3.5m에서 멈춘다. 결과는 구간 34개, 차로 68개다.
  - 연결 곡선: 교차로마다 들어오는 차로에서 나가는 차로로 이어지는 3차 베지어다(직진·좌회전·우회전, 유턴 제외). 열린 길 끝 2곳은 유턴으로 잇는다. 결과는 154개다.
  - 속도 상한: 직진 7m/s, 회전 3.5m/s, 유턴 2.5m/s. 다음 경로를 고르는 가중치는 직진 3, 회전 1이다.
  - 확인: 나갈 곳 없는 경로 0, 첫 차로에서 222개 경로 전부 도달 가능. 가장 급한 굽음은 41°/m(좁은 우회전)다. 처음에는 곡선 손잡이 최소 길이 3m 때문에 짧은 우회전이 꼬여서, 손잡이를 거리 비례(회전 0.4, 유턴 0.67)로 고쳤다.
- 실행(`TrafficNetwork`, `TrafficCar`)
  - 시작할 때 차 50대를 차로 길이에 비례해 서로 14m 이상 떨어뜨려 놓는다(시드 7). 종류 비율은 승용차 50%, 택시 20%, 밴 20%, 버스 10%이고 색은 종류별 목록에서 고른다.
  - 앞차 간격: 같은 경로와 다음 경로 위 차들의 거리로 계산한다(차마다 물리 검사를 하지 않는다). 사람·주민·소품은 앞쪽 짧은 범위를 3프레임마다 물리로 검사해 멈춘다.
  - 교차로: 한 번에 한 연결 곡선만 들어간다. 같은 곡선을 따라가는 뒤차는 이어서 들어갈 수 있고, 다른 방향 대기 차가 있으면 순서를 지킨다. 나갈 차로 앞에 자리가 없으면 정지선에서 기다린다(교차로 막힘 방지). 자리를 기다리는 동안에는 대기 순번을 내려놓아 다른 방향을 막지 않는다.
  - 플레이어와 부딪히면 이전 밴과 같은 넉백을 준다. 일시정지·정산 중에는 멈춘다.
- 차량 프리팹(`Prefabs/Traffic/`)은 기본 도형으로 만들었고 수치는 전부 시험값이다.

| 종류 | 크기(폭×높이×길이) | 순항 | 비고 |
|---|---|---|---|
| Car | 1.8×1.45×4.2m | 6m/s | 빨강·파랑·은색·검정·흰색 |
| Taxi | 1.8×1.45×4.3m | 6.5m/s | 노랑, 지붕 표시등 |
| Van | 1.9×2.0×4.8m | 5m/s | 흰색·회색 |
| Bus | 2.5×3.0×10m | 4m/s | 초록·파랑, 간격 3.5m |

- 차 수·비율·간격은 `Traffic` 오브젝트의 `TrafficNetwork`에서 바꾼다. 차별 속도는 각 프리팹의 `TrafficCar`에서 바꾼다.
- 차는 골목에 들어가지 않는다. 오리·맨홀 같은 사건은 충돌체가 없어 그대로 지나간다. 비둘기·주민·플레이어 앞에서는 멈춘다.
- 길을 고친 뒤에는 사건 자리 → 건물 → 교통 순서로 설치기를 다시 실행한다.
- 정리: 옛 `TrafficVehicle`·`TrafficRoute`·`TrafficJunction`, `TrafficVan.prefab`, `Van.mat`, 시범 차로·밴을 삭제했다.
- 미검증(플레이 확인 필요): 실제 흐름(막힘·끼임·추돌), 좁은 우회전에서 버스 뒷부분이 인도로 넘어가는지, 차 50대의 프레임 영향.
