# 배달 라이더 시뮬레이터 프로토타입 기획서

- 버전: 0.1
- 작성일: 2026-09-18
- 작업명: 배민라이더 시뮬레이터
- 프로젝트 환경: Unity 6000.3.23f1
- 문서 목적: 핵심 플레이와 예외 처리 규칙을 정하고, 첫 프로토타입의 구현 범위와 검증 기준을 공유한다.

## 1. 게임 개요

3인칭 3D 로우폴리 배달 시뮬레이터. 플레이어는 도보 배달로 시작해 제한된 하루 동안 주문을 수행하고, 돌발 상황을 수습하며 수익을 얻는다. 벌어들인 돈으로 관리비를 내고 자전거를 구매하며, 최종적으로 빚을 모두 갚는다.

핵심 경험은 주문의 거리와 보상을 비교하는 판단, 제한 시간 안에 이동하는 긴장감, 물리 충돌이 만드는 코믹한 상황, 도보에서 자전거로 성장하는 성취감이다.

## 2. 확정 사항과 설계 전제

### 사용자 확정 사항

| 항목 | 규칙 |
|---|---|
| 시점·그래픽 | 3인칭, 3D 로우폴리 |
| 시작 이동 방식 | 도보로 시작하고 이후 자전거 구매 |
| 동시 수행 주문 | 한 번에 한 건 |
| 주문 시간 시작 | 주문 수락 즉시 시작 |
| 시간 초과 | 주문은 유지되고 지각 보상 적용 |
| 하루 종료 | 신규 주문 수락을 막고 진행 중 주문까지 마무리 |
| 주문 포기 | 포기 기능 없음 |
| 음식 도난 | 상황에 따라 추격 회수 또는 음식점 재수령 |
| 배달 완료 | 해당 주문의 고객 주민에게 부딪혀 전달 |
| 주민 | 플레이어와 물리적으로 충돌 가능 |
| 관리비 부족 | 부족한 금액만큼 빚 증가 |
| 장기 목표 | 빚 전액 상환 후 엔딩 |

### 프로토타입용 제안

이하에서 별도 확정 사항이 아닌 조작, 수치, 우선순위, 세부 판정은 구현을 위한 초안이다. 플레이 테스트 결과에 따라 변경하며, 수치는 설정 데이터로 분리한다.

- PC 키보드·마우스 조작을 기준으로 한다.
- 작은 동네 한 곳에서 음식점과 고객 위치를 반복 활용한다.
- 하루 시작 시 주문 후보를 제공하고 완료 후 새로운 후보를 채운다.
- 음식 수령은 음식점 범위 안에서 상호작용 키로 수행한다.
- 이자, 차량 유지비, 음식 재수령 비용은 첫 프로토타입에서 적용하지 않는다.

## 3. 전체 게임 흐름

**하루 시작 → 주문 탐색·수락 → 음식점 이동·수령 → 고객에게 이동 → 고객과 충돌하여 전달 → 주문 탐색 반복 → 하루 정산 → 관리비 납부 → 성장·빚 상환 → 다음 날**

돌발 상황은 이동 도중 발생한다. 사고는 시간을 소모시키고, 도난은 음식 복구 단계를 추가한다.

빚을 모두 갚으면 다음 날로 넘어가는 대신 간단한 엔딩 연출을 재생한다.

## 4. 주문 선택과 수행

### 주문 탐색 UI

- 지도 위에 고객 프로필 마커로 주문 후보를 표시한다.
- 마커 선택 시 음식점과 고객 위치, 기본 보상, 지각 보상, 제한 시간, 요청 사항과 팁을 보여준다.
- 경로 판단을 위해 음식점과 고객을 서로 다른 아이콘으로 표시한다.
- 주문을 수락하면 해당 음식점과 고객을 강조한다.
- 진행 중에는 다른 주문의 수락을 비활성화한다.
- 하루가 끝나면 모든 신규 수락을 비활성화한다.

### 주문 상태

| 상태 | 플레이어 행동 | 다음 상태 |
|---|---|---|
| 주문 없음 | 지도에서 후보 선택 후 수락 | 음식 수령 전 |
| 음식 수령 전 | 음식점에 도착하여 상호작용 | 배달 중 |
| 배달 중 | 해당 고객에게 충돌 | 배달 완료 |
| 음식 분실 | 추격 회수 또는 음식점 재수령 | 배달 중 |
| 배달 완료 | 결과 기록·보상 지급 | 주문 없음 또는 하루 정산 |

지각 여부는 주문 상태와 별도로 기록한다. 제한 시간이 지나도 음식 수령, 복구, 전달을 계속할 수 있다.

### 배달 완료 판정

다음 조건을 모두 만족한 물리 충돌에서 한 번만 완료한다.

1. 활성 주문이 존재한다.
2. 해당 주문의 음식을 보유하고 있다.
3. 충돌 상대가 해당 주문의 고객이다.
4. 해당 주문이 아직 완료되지 않았다.

- 다른 주민과 충돌해도 배달은 완료되지 않는다.
- 음식 수령 전이나 음식 분실 중에는 고객에게 충돌해도 완료되지 않는다.
- 최소 충돌 속도는 요구하지 않는다. 가볍게 부딪혀도 전달한다.
- 충돌 직후 주문을 완료 처리하고 고객 반응·음식 전달 효과·획득 금액을 표시한다.
- 고객이 밀려나더라도 동일한 주민 식별자를 기준으로 판정하고, 목적지 마커가 고객을 따라간다.
- 고객이 맵 밖으로 떨어지거나 접근 불가능한 곳에 끼면 안전 위치로 복귀시킨다.
- 도보와 자전거 모두 같은 고객 판정 규칙을 사용한다.

## 5. 시간과 하루 종료

### 두 종류의 타이머

- 하루 타이머: 영업 중 남은 시간. 0이 되면 신규 주문 수락을 막는다.
- 주문 타이머: 수락 순간부터 음식 수령·사고·음식 복구 시간을 포함해 진행한다.
- 주문 마감 시각 이내 완료하면 정시, 마감 시각을 넘겨 완료하면 지각이다.
- 주문 마감 이후에는 남은 시간 대신 초과 시간을 표시한다.
- 지도와 주문 상세 UI를 열어도 시간은 흐른다. 일시정지 메뉴에서는 함께 멈춘다.

### 하루 종료 처리

| 종료 시점 상황 | 처리 |
|---|---|
| 활성 주문 없음 | 즉시 정산 |
| 음식 수령 전 | 수령과 전달을 마칠 때까지 진행 |
| 배달 중 | 전달 완료까지 진행 |
| 음식 분실 중 | 복구 후 전달 완료까지 진행 |

초과 근무 중에도 주문 타이머와 지각 판정은 유지한다. 마지막 주문을 완료하면 신규 후보 생성 없이 정산한다. 초과 근무 자체에 별도 벌금은 부과하지 않는다.

## 6. 보상과 요청 사항

**주문 수익 = 정시 또는 지각 기본 보상 + 달성한 요청 사항의 팁**

- 초기 예시 보상: 정시 5,000원, 지각 1,000원.
- 요청 사항은 수락 전에 공개하고 주문 수락과 함께 적용한다.
- 요청 사항 실패는 주문 완료를 막지 않고 해당 팁만 지급하지 않는다.
- 첫 요청 사항 예시: 음식 수령 후 일반 주민과 충돌하지 않으면 팁 지급.
- 전달 대상 고객과의 완료 충돌은 위 요청 사항의 실패로 계산하지 않는다.
- 기본안에서는 지각해도 요청 사항을 지켰으면 팁을 받는다.
- 주문 보상은 완료 시 한 번 지급하고 정산 화면에서는 합계를 보여준다.

## 7. 돌발 상황

### 사고: 배달 지연

- 특정 구역에서 차량·장애물과 충돌하면 플레이어가 밀려나거나 넘어진다.
- 짧은 조작 불가 시간 이후 다시 이동할 수 있다.
- 사고 중에도 두 타이머는 계속 진행한다.
- 첫 구현은 물리적 밀림과 짧은 회복으로 표현하고, 정교한 전신 래그돌은 후순위로 둔다.
- 맵 밖으로 떨어지거나 끼이면 최근 안전 지점으로 복귀한다. 주문과 지각 상태는 유지한다.

### 도난: 배달 진행 차단

- 음식을 보유한 상태에서만 발생한다.
- 도난 즉시 음식 보유 상태를 해제하고 복구 목적지를 표시한다.
- 추격형 사건: 도둑과 충돌하면 음식을 되찾는다.
- 재수령형 사건: 음식점으로 돌아가 상호작용하면 음식을 다시 받는다.
- 추격형에서도 도둑이 도주하거나 접근 불가능해지면 음식점 재수령으로 전환한다.
- 회수와 재수령 중 하나가 성공하면 나머지 복구 경로를 종료해 중복 획득을 막는다.
- 음식을 잃은 동안 추가 도난은 발생하지 않는다.
- 복구 중 주문 마감이나 하루 종료가 발생해도 복구 경로를 유지한다.

### 발생 규칙

- 구역형: 지정 트리거 진입 시 확률적으로 사건을 선택한다.
- 시간형: 지정 간격마다 발생 조건을 검사해 적합한 사건을 선택한다.
- 두 방식이 동시에 사건을 발생시키지 않도록 공통 재발 대기시간을 적용한다.
- 첫 프로토타입에서는 사건 한 개를 수습 중일 때 다른 강제 사건을 발생시키지 않는다.
- 수령 위치·고객 바로 주변은 사건 발생 제외 구역으로 둔다.
- 초과 근무 중에는 신규 강제 사건을 발생시키지 않고 기존 사건만 수습한다. 일반 물리 충돌은 유지한다.

## 8. 주민과 월드

- 작은 동네에 음식점, 고객 대기 장소, 도로·보행 공간, 장애물, 사건 구역을 배치한다.
- 일반 주민은 정지 또는 간단한 왕복 이동을 한다.
- 주민은 물리 충돌과 가벼운 밀림 반응을 제공한다.
- 고객은 머리 위 프로필과 바닥 표시로 일반 주민과 구분한다.
- 모든 음식점·고객·복구 지점은 도보로 접근 가능해야 한다.
- 자전거가 없어도 모든 주문을 완료할 수 있게 설계한다.

## 9. 정산·성장·빚

### 정산 순서

1. 배달별 정시·지각, 요청 사항 성공 여부, 보상·팁·리뷰 표시.
2. 오늘 총수익과 배달 건수 표시.
3. 보유 현금에서 하루 관리비 차감.
4. 현금이 부족하면 현금을 0원으로 하고 부족분만 빚에 추가.
5. 남은 현금으로 자전거 구매 또는 빚 상환.
6. 빚이 0원이면 엔딩, 남아 있으면 다음 날 시작.

관리비 납부 전 현금을 C, 관리비를 F, 기존 빚을 D라고 할 때:

- 납부 후 현금 = max(0, C − F)
- 납부 후 빚 = D + max(0, F − C)

예: 현금 2,000원, 관리비 3,000원이라면 현금은 0원이 되고 빚이 1,000원 증가한다.

빚 상환은 플레이어가 선택하며 보유 현금과 남은 빚을 넘겨 상환할 수 없다. 빚이 늘어나는 것만으로 게임 오버가 되지는 않는다.

### 자전거 성장

- 정산 후 상점에서 자전거를 한 번 구매하면 다음 날부터 사용 가능하다.
- 도보보다 빠른 이동을 주요 이점으로 한다.
- 초기안은 구매 후 이동 모드가 자전거로 바뀌는 단순 구조로 하고 승하차는 후순위로 둔다.
- 추가 장비와 단계별 업그레이드는 핵심 반복 흐름 검증 후 확장한다.

### 리뷰와 엔딩

- 리뷰는 정시·지각·요청 사항 결과에 맞는 짧은 문구로 표시한다.
- 첫 버전에서 리뷰는 별도 평판 수치나 주문 확률에 영향을 주지 않는다.
- 엔딩은 빚 상환 완료 문구와 누적 일수·배달 건수를 보여주는 짧은 화면으로 구현한다.

## 10. 화면과 조작 초안

| 화면 | 주요 정보·기능 |
|---|---|
| 플레이 HUD | 남은 하루 시간, 주문 남은 시간·초과 시간, 현재 목표, 현금 |
| 지도·주문 선택 | 고객 프로필, 음식점, 플레이어 위치, 주문 상세, 수락 |
| 사건 안내 | 사고 회복 상태, 도난 안내, 회수·재수령 목적지 |
| 배달 완료 알림 | 정시·지각, 기본 보상, 팁, 합계 |
| 하루 정산 | 배달별 결과·리뷰, 총수익, 관리비, 현금, 빚 |
| 성장·상환 | 자전거 구매, 빚 상환, 다음 날 시작 |

조작 초안: WASD 이동, 마우스 카메라 회전, E 음식 수령·재수령, M 지도, Esc 일시정지. 고객 전달과 도둑 회수는 충돌로 수행한다. 자전거도 같은 이동 키를 사용한다.

사건 확률과 실제 이동 속도는 맵 크기를 정한 뒤 조정한다. 주문 제한 시간은 정상 도보 이동으로 정시 완료가 가능한지 먼저 확인한다.

## 12. 구현 범위와 순서

### 1단계: 핵심 배달 검증

- 작은 테스트 동네, 도보 이동, 3인칭 카메라.
- 지도 위 주문 후보 3개와 단일 주문 수락.
- 음식 수령과 해당 고객 충돌 전달.
- 하루·주문 타이머, 지각 보상, 마지막 주문 마무리.
- 기본 주민 충돌, 사고 사건 1종, 배달 결과 정산.

### 2단계: 완결된 반복 플레이

- 도난 사건과 추격 회수·재수령 경로.
- 구역형·시간형 사건 발생과 중복 방지.
- 요청 사항 1종과 팁, 결과별 리뷰.
- 관리비, 부족분의 빚 전환, 자전거 구매, 빚 상환.
- 다음 날 반복과 간단한 엔딩.
- 하루 정산 종료 시 현금·빚·자전거 보유·다음 일차 저장. 하루 도중 재개는 후순위.

### 후순위

넓은 도시, 복잡한 교통 AI, 정교한 래그돌, 자전거 승하차, 다양한 장비, 다수의 요청 사항, 본격적인 컷신은 초기 구현에서 제외한다. 다중 주문과 주문 포기는 현재 확정 규칙에 포함하지 않는다.

## 13. 프로토타입 완료 기준

- 도보로 주문 선택부터 수령·고객 충돌 전달까지 한 건을 완료할 수 있다.
- 주문 타이머는 수락 즉시 시작하고 수령·사고·복구 중에도 진행한다.
- 정시와 지각 배달에서 서로 다른 보상이 한 번만 지급된다.
- 일반 주민 충돌, 음식 없는 고객 충돌, 반복 접촉으로 잘못 완료되거나 중복 지급되지 않는다.
- 하루 종료 후 새 주문을 수락할 수 없고 활성 주문 완료 후 정확히 한 번 정산한다.
- 음식 분실 중 하루가 끝나도 복구하고 최종 전달할 수 있다.
- 추격 회수와 재수령 양쪽을 확인하고, 도둑을 놓쳐도 진행이 막히지 않는다.
- 완료용 고객 충돌이 요청 사항 실패로 계산되지 않는다.
- 관리비 부족분만 빚에 추가되고 현금이 음수가 되지 않는다.
- 자전거 구매 후 다음 날 이동 성능이 바뀌며 구매가 중복 결제되지 않는다.
- 현금 한도 내에서 빚을 상환할 수 있고 전액 상환 시 엔딩에 도달한다.
- 고객·플레이어가 맵 밖으로 이탈해도 복귀하여 주문을 마칠 수 있다.

## 14. 테스트에서 확인할 질문

- 주문 후보를 비교할 때 거리와 보상 사이에 의미 있는 선택이 생기는가?
- 고객에게 부딪히는 전달 방식이 명확하고 반복해도 재미있는가?
- 사고와 도난이 긴장감을 주면서도 복구 가능한 수준인가?
- 지각 보상으로도 배달을 끝낼 동기가 남는가?
- 마지막 주문을 마무리하는 초과 근무가 과도하게 길어지지 않는가?
- 자전거 구매와 빚 상환 중 어느 쪽을 선택할지 고민이 생기는가?

위 항목을 검증한 뒤 콘텐츠 수와 장기 진행 길이를 확장한다.
