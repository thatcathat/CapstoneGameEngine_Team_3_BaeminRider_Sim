# 트래픽 시범 구현

- 적용일: 2026-10-13
- 단계: 소규모 시범 씬 제작·저장, 컴파일 및 정적 배치 확인 완료. 실제 플레이는 미실행.
- 씬: `Assets/_Game/Scenes/TrafficPilot.unity`
- 원본: `GameScene`과 `Map.prefab`은 이번 작업에서 저장하거나 교체하지 않았다. 시범 씬은 기존 게임 씬의 복사본이다.
- 범위: 4구역 전체 맵 전환에 앞서 사용할 대표 도로·교차로·경사·배달 연결. 전체 22개 도로와 실제 지리 배치는 아직 적용하지 않았다.

## 구성

| 항목 | 구현 |
|---|---|
| 도로 | 폭 10m 남북 큰길, 동서 큰길, 중앙 교차로, 보도, 남서쪽 차량 없는 골목 |
| 고저차 | 북쪽 Z=12~44m에서 0→1.4m로 부드럽게 상승. 최대 경사 약 6.56%, 북쪽 끝은 평탄 |
| 교통 | 일반 차량 3대, 높이를 가진 순환 차로 2개, 교차로 선착순 예약 |
| 운행 | 앞차·보행자·고정 장애물 감지, 정지·재출발, 커브·경사 감속 |
| 충돌 | 접촉 시 차량 정지. 이동 중 플레이어 접촉은 제한된 밀림과 짧은 회복 요청 |
| 배달 | 기존 주문 6개 및 음식점 3곳·고객 3명 연결 유지. 목적지들은 차도 밖 |
| 사건 | 기존 사건 5곳과 설정 유지. 시범 맵의 평탄한 공간으로 이동, 추격 경유점 재배치 |
| 지도 | 시범 도로 배경과 X/Z=-54~54 표시 범위로 변경, 기존 마커·주문 UI 유지 |

모든 수치는 시범용이다. 실제 동네의 도로 고도·교통량이나 확정 밸런스가 아니다. 건물은 단순한 시범 상점이며 기존 동네 외형 전체를 이식한 상태가 아니다.

## 코드와 동작 정책

- `TrafficRoute`: 고도를 포함한 닫힌 차로의 거리 기반 위치·방향 계산. 차량은 이 경로를 따라 움직인다.
- `TrafficJunction`: 대기열에서 한 대씩 교차로를 예약하고 뒷부분까지 빠져나간 뒤 해제한다. 신호등·차선 변경·추월은 없다.
- `TrafficVehicle`: 경로를 따라 차량 크기로 장애물을 검사한다. 내리막에서도 속도를 제어하며, 장애물이 급히 들어오면 이동량을 제한한다. 접촉 중에는 멈춰 지속적으로 밀지 않도록 한다.
- `RiderMotor`: 선택 가능한 경사 추종·접지 중 중력 상쇄·가까운 지면으로의 보정·최근 접지 위치 기준 추락 복귀를 추가했다. `followSlopes`는 시범 씬에서만 켰다. 사고 발사 중에는 접지 보정을 적용하지 않는다.
- 차량 회복과 기존 사건 회복의 소유 상태를 구분했다. 차량은 `IncidentDirector.TryStart`를 호출하지 않으며 음식·주문·도난 상태를 변경하지 않는다. 새로운 기존 사고가 시작되면 해당 사고 처리가 우선한다.
- 지도 중에는 시간이 흐르고 차량도 운행한다. 일반 차량은 플레이어를 장애물로 감지해 정지하며 지도 확인 중에는 차량 넘어짐 요청을 받지 않는다. 일시정지와 정산에서는 차량도 정지한다.
- 차량은 처음 배치한 3대를 계속 사용한다. 막힘을 이유로 화면 안에서 차량을 순간이동시키거나 플레이어를 강제로 옮기지 않는다. 장애물이 비켜나면 다시 진행하는 정책이다.
- 차량 모델은 키네마틱 차체와 간단한 시각 바퀴를 사용한다. 실제 차량 서스펜션·중량 시뮬레이션은 구현 범위가 아니다.
- 도둑의 교통 우회 AI는 추가하지 않았다. 차량에 막혀 추격이 끝나는 경우에도 기존 재수령 복구 경로가 유지되며, 실제 교차 상황은 사용자 확인 항목이다.

첫 설정: 평지 최고 5m/s, 커브 2m/s, 경사 3.5m/s, 가속 2m/s², 제동 8m/s². 차체 크기 1.8×1.2×3.6m. 플레이어 차량 회복은 약 1.1초, 회복 이후 재피격 방지 1초다. 기존 사건 스팟의 발생 횟수·쿨타임 규칙은 변경하지 않았다.

## 제작 도구

Unity 메뉴 `Delivery Rider → Create Traffic Pilot`으로 제작한다. 이미 시범 씬이 있으면 기존 씬을 열기만 하며 덮어쓰지 않는다. 미저장 씬 또는 Play 모드에서는 제작을 중단한다. 씬·메쉬·머티리얼·프리팹·메타데이터는 Unity API를 통해 생성했다.

시범 씬은 타이틀의 기본 진입 씬이나 빌드 목록을 바꾸지 않는다. Unity에서 `TrafficPilot.unity`를 직접 열고 실행한다. 기존 정산 화면의 다시 배달하기는 원래 `GameScene`으로 이동하므로, 시범 구간을 반복하려면 Play를 종료하고 시범 씬에서 다시 실행한다.

## 이전 트래픽 시범 제작 시 확인 결과

- Unity 컴파일 완료, `compilationFailed=false`.
- 시범 씬 저장 완료, 미저장 변경 없음, Play 모드 미진입.
- 차량 3대·방향광 1개, 누락 컴포넌트 0개.
- 주문 6개의 정의·수령지·고객 참조 누락 없음.
- 차로를 1m 간격으로 샘플링해 차량 차체와 여유 폭으로 검사: 기존 차량을 제외한 정적 장애물 겹침 없음.
- 플레이어·고객·주민의 초기 캡슐 배치에서 다른 충돌체 겹침 없음.
- 지도 배경은 새 `TrafficPilotMap.png`로 연결됨.
- 생성 요청은 에디터 연결의 5초 응답 제한을 넘겨 시간 초과 로그 1건을 남겼지만, 후속 조회로 씬·프리팹 생성과 최종 저장을 확인했다. 게임 스크립트 컴파일 오류와 구분한다.

이 확인은 실제 차량 운행, 교차로 대기 해소, 충돌 체감, 경사 이동, 카메라 시야의 플레이 검증을 대신하지 않는다.

## 사용자 확인 순서

1. 시범 씬에서 Play를 누르고 주문을 선택한다. M으로 지도를 닫고 남쪽 시작 보도에서 큰길로 접근한다.
2. 차량 앞에 서면 멈추는지, 옆으로 비켜나면 재출발하는지 확인한다. 지도를 열었을 때도 계속 밀리지 않아야 한다.
3. 중앙 교차로에서 차량이 서로 겹치지 않고 한 대씩 통과하는지 확인한다.
4. 북쪽 언덕을 양방향으로 이동하고 입력을 놓아 뒤로 미끄러지는지, 정상에서 불필요하게 튀는지 확인한다.
5. 각 음식점의 주문을 수령·전달한다. 북쪽 평탄한 수령지와 고객에 도보로 접근할 수 있어야 한다.
6. 차량 측면 접촉과 기존 사고·도난을 비교한다. 차량 접촉만으로 음식이 없어지거나 도둑 추격이 취소되어서는 안 된다.
7. 일시정지·재개와 하루 종료 후 마지막 배달을 확인한다.

문제가 없다면 다음 단계에서 4구역 도로 데이터에 차로·횡단 공간을 넣고, 경사 시야·전체 사건 밀도·배달 제한 시간을 함께 조정한다. 인라인, 신호등, 폭주 트럭, 전체 교통 확장은 이번 시범 범위에 포함하지 않는다.

## 추가 구현: 교차로 대기와 접촉형 문

2026-10-13 통합 첫 묶음의 코드 변경이다. 교차로 진입 전에 장애물로 막힌 차량은 예약을 놓아 다른 차량의 진행을 막지 않도록 했다. 진입 후에는 뒷부분이 나갈 때까지 예약을 유지한다.

`SwingDoorHazard`는 접근 → 0.8초 예고 → 0.45초 문 열림 → 잠시 유지 → 무해한 닫힘 순서로 동작한다. 접근 범위 진입만으로 사고를 적용하지 않는다. 열린 각도 사이를 2도 이하로 나누어 문짝과 플레이어 캡슐의 겹침을 검사하고, 접촉한 회차에는 한 번만 반응한다. 수치는 시범용이다.

- 경고등과 짧은 임시 합성음을 제공한다. 문 충돌체는 플레이어를 벽에 끼우지 않도록 물리적으로 밀지 않고 접촉 검사에 사용한다.
- `RiderMotor.TryContactCrash`를 차량과 문이 공유한다. `IncidentDirector`와 음식·주문 상태를 변경하지 않으므로 접촉이 기존 추격을 취소하지 않는다.
- 지도 중에는 새 예고를 시작하지 않는다. 진행 중 지도를 열면 해당 회차의 피격을 해제한다. 일시정지에서는 멈추며 정산·비활성화에서는 문 자세와 경고를 정리한다.
- 기본 재활성화는 새 주문 + 충분히 멀리 벗어남이다. 시범 설치에서는 반복 확인을 위해 닫힌 후 8초 + 접근 범위를 벗어나 4m 이상 떨어짐으로 설정한다.
- 설치 메뉴: `Delivery Rider → Install Door Hazard Pilot`. `TrafficPilot` 남쪽 보도 X=-8, Z=-29에 문 1개를 만든다. 기존 문이 있으면 덮어쓰지 않고, 미저장 씬이 있으면 중단한다.

**현재 확인 수준:** 코드 검토와 별도 컴파일 성공 후, 사용자 Refresh로 에디터 연결이 복구되었다. Unity 에디터에서 `compilationFailed=false`, 컴파일 종료를 확인하고 설치 도구를 실행했다. `TrafficPilot`에 문 1개(X=-8, Y=0.03, Z=-29)를 생성·저장했으며 필수 참조 누락 0개, 씬 전체 누락 스크립트 0개, 미저장 변경 없음, Play 모드 미진입을 확인했다. 원본 씬과 직렬화 파일을 직접 편집하지 않았다. 실제 플레이 미실행.

문 설치는 완료했다. 사용자 확인은 시작 보도에서 남쪽 문에 접근해 예고를 보고 피하기, 문짝에 접촉하기, 추격 중 접촉하기, 지도·일시정지 중 동작, 충분히 벗어난 뒤 재진입 순서로 진행한다. 문 접촉만으로 음식이 없어지거나 추격이 끝나서는 안 된다.

전체 맵의 후속 제작 기준은 [도로·고도 배치 초안](MapLayout/README.md)에 있다.

## 추가 구현: 타이어와 문 연쇄

2026-10-13, `RollingTireHazard` 1종을 두 위치에 설치했다. `Delivery Rider → Install Tire Hazard Pilot`은 기존 설치가 있으면 덮어쓰지 않는다.

| 배치 | 활성화와 이동 |
|---|---|
| `DoorChainTire` | 남쪽 문 피격이 실제 수락되면 0.8초 예고 후 출발. Z=-31, X=6.5→-5.5의 평지 12m 경로 |
| `SlopeTire` | 북쪽 서편 보도 X=-6.5, Z=32.5~37.5 부근에 접근하면 예고 후 Z=40→18 내리막 경로 |

- 접촉은 반경 0.55m 구체로 근사한다. 시작 겹침과 프레임 전체 이동 구간을 검사해 빠른 타이어가 플레이어를 통과하지 않도록 했다. 시각 모델은 구멍이 있는 로우폴리 타이어와 회전 표시다.
- 지면에 맞춰 작성된 경로를 따라 굴러가며 경사 방향에 따라 속도가 변한다. 자유 낙하·자유 회전하는 Rigidbody 시뮬레이션이 아니다. 시작 4m/s, 최대 7m/s, 최대 수명 8초는 시험값이다.
- 고정 장애물·차량이 먼저 가로막으면 종료한다. 플레이어에 대해서는 한 회차 한 번만 접촉을 소비하며, 실제 피격이 거절되어도 같은 회차에서 나중에 다시 때리지 않는다.
- 문을 피하면 연쇄용 타이어도 출발하지 않는다. 문 피격 후에도 타이어를 피할 수 있으며, 연쇄 피격을 강제로 보장하지 않는다. 움직이는 차량이 연쇄 경로를 막을 수도 있다.
- 서로 다른 문·타이어 피격은 0.35초 최소 간격을 두고 기존 접촉 회복을 갱신할 수 있다. 충격 속도는 대체한다. 실제 수락된 피격만 8초 창으로 `RiderMotor.HazardChainCount`에 집계하며 연쇄 HUD·보상은 추가하지 않았다.
- 일반 차량에는 연쇄 허용을 적용하지 않았다. 기존 사고가 이동 상태를 소유하면 문·타이어 충격은 거절된다. 접촉 코드가 `IncidentDirector`나 음식·도둑 상태를 바꾸지 않는다.
- 지도 열림은 진행 중 타이어를 종료한다. 일시정지는 이동·예고·재장전을 멈춘다. 정산의 timeScale=0 상태에서도 Update에서 문·타이어를 정리한다. 비활성화 시 문 이벤트 구독을 해제하고 타이어를 숨긴다.
- 기본 재활성화는 다음 주문이다. 이번 두 배치는 반복 확인용으로 종료 후 8초 경과, 접근 범위 이탈, 출발점에서 4m 이상 떨어짐 조건을 쓴다. 문 연쇄용은 다시 문에 맞아야 재출발한다.

**확인 결과:** Unity 에디터 컴파일 오류 없음. 시범 씬에 타이어 2개 생성·저장, 필수 참조 누락 0개, 문 연쇄 연결 확인, 씬 전체 누락 스크립트 0개, 미저장 변경 없음. 두 경로를 0.2m 이하 간격의 총 226개 위치에서 반경 0.55m로 검사해 현재 씬의 충돌체 겹침 없음. 실제 이동·움직이는 차량과의 교차·연쇄 체감은 플레이 미검증이다.

**사용자 확인 순서:** 남쪽 문 예고를 피했을 때 타이어가 출발하지 않는지 → 문에 맞은 뒤 반대편에서 굴러오는 타이어를 피하거나 접촉하기 → 북쪽 서편 보도에서 언덕 타이어를 양방향으로 만나기 → 도난 추격 중 접촉해 음식 회수가 유지되는지 → 지도·일시정지·정산 후 숨은 재피격이 없는지 확인한다. 플레이 모드는 사용자가 직접 실행한다.
